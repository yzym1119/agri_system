## 2. 当前真实完成程度

| 能力 | 员工端 | 客户端 |
|---|---|---|
| 前端工程 | Uni-app/Vue3/TS，13个注册页面 | `mini-customer/` 不存在，不能构建或体验 |
| 身份 | 账号登录、实时权限/门店刷新、会话代次隔离 | 后端微信code登录和身份表存在；独立前端、当前身份读取/老客认领未闭环 |
| 库存 | 扫码/查货；目录按本店实际批次可售量 | 无公开客户目录；不能调用员工目录代替 |
| 收货/提货/配送 | 工程已接原业务入口、原请求或指纹恢复 | 本人订单详情/确认收货后端存在；前端与列表缺失 |
| 销售 | 单品、主销售单位、现金、当场交货/档案带出门店配送 | 待支付创建/支付预览/意图后端存在；创建安全重试、公开报价及真支付未闭环 |
| 角色配置 | 真实RBAC控制入口，本机个人常用项按员工/店隔离 | 客户本人资源范围；无员工角色切换 |
| 农技/培训/AI | 无正式业务模块，设备页录音不是农技采集 | 设计提案，无咨询/知识/AI工程与持久事实 |
| 验证 | 自动回归已过；此前模拟器只覆盖部分、且整合前后版本不同 | 无客户端端到端证据 |
| 正式发布 | 尚欠整合版逐页、手机、HTTPS、运维与岗位验收 | 不满足发布条件，不能宣称商城或AI已上线 |

## 3. 与后台/数据模型的一致与差异

| 项目 | 判断 | V2处理 |
|---|---|---|
| 同一库存、价格、订单事实 | 设计方向一致 | 强制复用 `InventoryLedgerService`、`ProductPricingService`、原订单/支付/售后应用服务，不建移动独立账 |
| 员工权限 | V1方向一致，部分“待补”已实现 | 按实际权限码、真实门店、本人指派读取；常用配置不授权限 |
| 库存含义 | 旧目录曾读 `inventory` 投影，与可出库量不一致 | 97040d6已改目录；查货页的账面/未预留余额仍不等于可售，标签不能混用 |
| 员工销售范围 | V1较宽，当前有意收窄 | V2首期仅现金单品，不含赊销/混支/改价/套餐；电脑后台仍保留原能力 |
| 套餐 | 后台POS支持独立报价，客户线上创建明确拒套餐 | 两端首期都不冒用单品展开卖套餐，另行扩展及专项验收 |
| 状态 | 旧提货实体注释有“产生拣货移动”遗留，与现契约冲突 | 以实际已SALE分配和服务实现为准，确认提货不再扣库；订单/配送/售后状态分别解释 |
| 金额 | `Order.payAmount`字段旧实体注释“实付”不足以表达当前口径 | 采用详情VO/资金事实：净应结算含赊销；已收、欠款、实还、退款分别展示 |
| 客户身份 | 同一customer复用成立；手机号自动认领不成立 | 明确当前OpenID映射无AppID字段；多客户端AppID接入前须扩身份范围，不能用测试号串账号 |
| 真支付 | 有意图/兼容确认，不是微信网关 | 不把shared-secret回调或客户端自确认当平台验签到账；主动确认默认关闭保持 |
| 农技数据 | 现有购买跟进不是农技个案 | case/entry/knowledge仅拟新增，逐阶段评审后迁移，不借订单备注塞新业务 |
| 视觉/页面 | V1三栏与现13页未一致 | 员工首期沿用工作台+业务页，不为凑旧方案新增空任务/我的；客户端导航单独设计 |

3. 涉及旧农技字段的细化仍可查10月29日共享文档；与V2冲突时按V2执行，涉及既有钱货实现按当前代码/AGENTS契约确认后更新文档。

优先级：员工整合验收 → 本人订单最小只读 → 客户公共入口及安全身份 → 知识/人工服务闭环 → 有限制的AI → 交易安全与真实支付。客户服务端可在员工收口后并行准备，但不能以此拖延员工核心可用性。

## 5. 后续维护规则

- 每次业务改动同时更新对应文档版本、接口表、字段/状态、验收行；提交说明写清影响范围。
- 接口标记仅三类：已存在（不等于已发布）、拟新增、须改造。不得把设计路径写成可直接调用API。
- 新表/字段必须提供现有结构不足、更简单方案、迁移与保留历史的回退策略；文档不构成自动执行DDL的授权。
- 每个验收记录至少包含提交、环境、角色、输入、预期/实际、请求身份/单据ID、API或SQL证据、截图/设备和结论；失败与未测不能记通过。
- 最新功能基线97040d6；本轮文档提交另记，不篡改旧验收记录。源码变更后重新核对，不承诺本文永远等同远端最新。

## 6. 本轮文档验证

已对当前13个员工注册页面逐条检查覆盖；11份相关文档本地链接、代码围栏及git空白检查通过。独立实施审查发现并修正两项：员工现金实收/找零不是现有手机能力；客户端意图发起与确认重放需区分状态与过期处理。补审未发现剩余可行动的重要不一致。只校验文档与指定提交的源码对应关系，本轮没有运行产品测试、部署或手机验收，不复用旧通过数声称新增结果。
