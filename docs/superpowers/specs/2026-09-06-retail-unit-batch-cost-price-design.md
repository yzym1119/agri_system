# 农资零售单位、批次、成本与价格事实链设计

## 目标

建立一条能在门店、后仓、主仓和跨店调货之间持续追溯的经营事实链：

```text
收货事实 -> 库存位置与批次 -> 补货/拣货事实 -> 销售事实 -> 实际成本与毛利
```

本设计不把业务决定交给系统。系统记录事实、完成换算、生成风险提示和保存授权痕迹；经营者决定采购单位、销售单位、货物去向、批次管理强度、价格和处置动作。

## 范围

本期覆盖：

- SKU 自定义库存基准单位及多单位换算。
- 采购收货、多批次到货、库存位置、补货和拣货的事实记录。
- POS/小程序销售的批次归属证据等级与成本计算。
- 建议价格、人工成交价和改价留痕。
- 库存、日期和毛利风险提示。

本期不覆盖：

- 自动禁售、自动报损、自动调拨、自动采购或自动改价。
- 全量 PDA/WMS 波次拣货、逐件序列号管理或强制逐件贴码。
- 营销、AI、支付和提成规则改造；这些模块后续只消费本设计产生的可信成本和销售事实。

## 核心原则

1. 单位由每个 SKU 自主定义，不存在全系统固定的入账单位。
2. 每个 SKU 选择一个库存基准单位，用于余额、批次数量和成本计算；它通常是最小可管理单位，但可以是箱、件、瓶、袋、公斤或其他经营者选择的单位。
3. 采购、销售、盘点、调拨、退货和报损都允许使用已启用业务单位。每张单据永久保留原始单位、原始数量、原始单价和当时换算系数。
4. 批次的真实归属来自扫描或仓储作业事实。系统不得将规则分摊伪装为真实批次追溯。
5. 风险提示不等于业务禁令。临期、日期未知、成本异常、低于参考底价都由具备权限的人做最终决定，并保存理由。

## 单位模型

### 业务能力

一个商品可同时按件采购、按箱/瓶销售、按瓶盘点。例如：

```text
库存基准单位：瓶
采购单位：件，1 件 = 288 瓶
销售单位：箱，1 箱 = 24 瓶；瓶，1 瓶 = 1 瓶
```

采购 1 件增加 288 瓶库存；销售 1 箱扣减 24 瓶库存。业务单据展示和对账仍使用“1 件”或“1 箱”，不会把经营动作改写成“288 瓶”或“24 瓶”。

### 数据结构

新增 `product_unit`，所有单位直接换算到本 SKU 的库存基准单位，避免多级单位链、循环换算和前后端各自推导：

```text
product_unit
- id
- product_id
- unit_name
- base_quantity_per_unit
- is_base_unit
- allow_purchase
- allow_sale
- allow_inventory
- allow_transfer
- barcode
- status
- created_at / updated_at
```

约束：每个商品仅一个启用的 `is_base_unit=1`，其 `base_quantity_per_unit=1`；所有启用业务单位必须大于零且直接对应同一基准单位。

现有 `main_unit`、`aux_unit`、`main_to_aux_ratio` 保留为兼容字段和迁移来源，但不再作为新业务的唯一单位模型。新接口从 `product_unit` 校验单位和换算；旧接口继续按主辅单位工作直至迁移完成。

## 收货、库存位置与批次

### 分层职责

- 采购单：表达采购计划和供应商约定，不直接创造库存。
- 收货单/收货行：表达每次实际到货，可部分收货、多次收货。
- 收货批次：表达同一 SKU 的实际厂家批号、日期、数量和成本事实。
- 库存位置：表达货当前在前台货架、门店后仓、主仓、其他门店或具体库位。

一采购行可拆成多个收货批次；一个采购行也可在不同日期分多次收货。

```text
采购行：10 件
收货批次 A：6 件，厂家批号 X，日期已知
收货批次 B：4 件，厂家批号 Y，日期未知
```

每个批次至少保存：原始收货单位/数量/单价、换算后的基准数量和单位成本、厂家批号或内部收货批号、生产日期、有效期、供应商、收货人、验收凭证和日期事实状态。

日期未知是“系统无法判断日期风险”的事实，不等于安全、过期或禁止销售。

### 轻量位置模型

本期不建设完整 WMS。位置先支持前台货架、门店后仓、主仓、其他门店四类，并为以后细化货架号/库位预留标识。

```text
inventory_location
- id
- store_id
- location_type: SALES_FLOOR / STORE_BACKROOM / CENTRAL_WAREHOUSE / OTHER_STORE
- code / name
- status
```

批次库存拆分为“批次 + 位置”的余额。调拨、补货和拣货都是位置间的库存移动，必须记录原始业务单位、换算数量、操作人和时间。

## 销售与批次归属

收银员只扫描商品码或批次码，不选择批次。

```text
POS 扫 SKU
  -> 门店前台直接交付，或创建库房取货需求
  -> 拣货/补货作业提供批次或位置事实
  -> 系统记录本销售行的批次归属及证据等级
```

批次归属证据等级：

| 等级 | 来源 | 含义 |
|---|---|---|
| `SCANNED` | 批次码、外箱码、单批次货位码 | 已扫描到批次事实，可精确追溯 |
| `FULFILLMENT_CONFIRMED` | 拣货或补货人员确认货位/批次 | 作业人员确认的批次事实 |
| `RULE_ALLOCATED` | 管理者为该商品/位置选择的分摊规则 | 按 FEFO、FIFO 或指定规则的账务归属，不宣称逐件真实 |
| `UNKNOWN` | 混批且没有扫描或作业事实 | 仅确认 SKU 销售，批次未知 |

### 三类典型场景

1. 前台货架同 SKU 混批，顾客直接购买：POS 扫 SKU；按该位置配置的规则分摊，或明确记录为 `UNKNOWN`。
2. 前台无货、后仓/主仓取货：POS 创建取货需求；取货人扫描单批次货位或外箱批次码，或确认批次后完成拣货，销售行记录实际批次。
3. 高值、易召回或高风险商品：经营者可要求按外箱、周转箱或最小销售包装扫描批次码，形成 `SCANNED` 证据；不要求所有商品逐件贴内部码。

厂家 EAN/GS1 码仅能识别 SKU 时，不能被解释为批次扫描。厂家码含批号/日期，或门店内部批次标签可被扫描时，才形成批次事实。

## 成本、毛利和价格

### 成本

批次记录实际单位成本。销售毛利使用销售行最终关联批次的成本：

- `SCANNED` 和 `FULFILLMENT_CONFIRMED` 使用实际批次成本。
- `RULE_ALLOCATED` 使用规则分配后的批次成本，并保留规则版本。
- `UNKNOWN` 不虚构批次成本；报表可使用单独标记的估算成本，但必须与实际批次毛利分开显示。

商品 `avg_cost_price` 保留为分析和展示缓存，不作为销售毛利、库存价值或提成结算的唯一事实。历史成本应通过迁移校验后单独修复，不能因模型上线而静默重算。

### 价格

价格建议由一个服务统一计算，输入为：

```text
SKU + 门店 + 渠道 + 客户层级 + 销售单位 + 生效区间
```

每个销售单位可配置独立建议价格。例如瓶建议价 10 元、24 瓶一箱建议价 220 元；箱价不强制等于瓶价乘以 24。

最终成交价仍由经营者决定。人工改价保存：建议价、成交价、差额、原因、操作人、确认人、时间和价格规则版本。参考底价只决定风险提示和授权层级，不自动拒单。

## 风险提示与人工决策

系统输出的内容是事实和建议：日期已知/未知、临期、过期、库存不足、积压、批次成本、建议价、实际毛利和分摊证据等级。

经营者可选择继续销售、改价、补货、跨店调拨、退供、报损、暂停补货或暂不处理。每项决定保存实际选择、理由、责任人和时间；系统不自动停售、不自动报损、不自动调拨或自动采购。

库存阈值可由销量、供货提前期、季节和当前库存生成建议，经营者可以采用、修改或忽略。未配置阈值的商品不应被伪装为“安全”。

## 迁移与兼容

1. 现有 SKU 由管理员确认库存基准单位；系统不猜测“旧主单位是否为箱、旧辅单位是否为瓶”。
2. 从现有主辅单位生成初始 `product_unit` 草稿，管理员确认后启用。新单位模型启用前，旧接口和旧前端继续工作。
3. 现有库存按旧主单位解释并迁入基准数量；原始数量和迁移换算关系永久保留。
4. 现有价格需明确价格所属销售单位后才进入新价格引擎；不能自动推定其为箱价或瓶价。
5. 现有批次无日期的统一标记为日期未知，不修改历史日期，也不自动改变可售状态。
6. 新收货、新补货、新拣货和新销售优先使用新事实链；历史订单保持只读，报表明确区分历史估算成本和新链路实际成本。

## 验收标准

- 同一 SKU 可按件采购、按箱/瓶销售、按任意启用单位盘点和调拨，余额按该 SKU 基准单位准确累计。
- 一采购行支持多批次、部分收货和多次收货，且每批次可追溯到收货事实。
- 前台混批销售可明确标识为规则分摊或批次未知；库房取货可通过批次/货位扫描或取货确认形成精确批次事实。
- POS 不需要人工选批次；扫码失败或无码时仍可手工检索 SKU 完成销售。
- 一销售行可关联多个批次，实际毛利可回溯到批次成本和批次归属证据等级。
- 价格按销售单位计算，人工改价和风险处置均留下建议、最终决定、理由与责任人。
- 临期、日期未知、低毛利和库存风险只提示，不自动阻断或执行经营动作。

## 测试边界

- 单位换算：件/箱/瓶混合采购销售、精度、禁用单位、历史换算快照。
- 收货批次：一采购行多批次、多次收货、部分收货、日期未知和成本不同。
- 位置移动：前台补货、后仓取货、跨店调拨、批次余额守恒。
- 销售归属：`SCANNED`、`FULFILLMENT_CONFIRMED`、`RULE_ALLOCATED`、`UNKNOWN` 四种证据等级及毛利显示。
- 价格：不同销售单位独立价格、建议价、人工成交价和审计记录。
- 迁移：旧主辅单位、历史库存、历史价格和无日期批次不被静默改变。
