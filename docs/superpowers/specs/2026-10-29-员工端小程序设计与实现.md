# 员工端小程序详细设计与实现文档

> 历史设计/计划（2026-10-29快照），保留追溯。当前范围、实现状态、接口与实施验收请读[V2.0设计与实施手册](../../current/06-员工端设计与实施手册.md)；本文“未创建/拟新增/未开放”等描述不得直接当作当前事实。


日期：2026-10-29。状态：待评审设计，尚未创建员工小程序工程。总体依据见[调研与决策](2026-10-29-双端小程序-调研与总体决策.md)。

## 1. 目标、人员及边界

员工拿手机完成收货、查货、交货、送货、农情采集和学习。老板能看到待审核问题与风险，但不把整套电脑后台塞进手机。第一期不做工资审批、营销配置、角色授权、供应商财务付款或完整移动ERP。

| 使用者 | 高频任务 | 禁止扩大为 |
|---|---|---|
| 库管 | 收货核对、批次与货位、待交货核对 | 默认查全部客户欠款、任意调价 |
| 销售 | 查价、客户查询、开单/收款登记、查看本次请求结果 | 修改库存账、自动通过赊销授信 |
| 配送员工 | 本人任务、导航、电话、剩余物料核对及签收 | 读取其他配送员全部客户、重复扣库存 |
| 新员工/农技助理 | 标准资料采集、回访、已审核SOP、练习 | 自行发布未审核药剂方案、冒用老板签名 |
| 老板 | 任务概览、复杂咨询审核、授权范围内业务 | 默认承诺全天候人工服务 |

一人可兼任多个岗位，由已有角色权限组合决定；不为每种岗位再造一套身份库。

## 2. 信息架构与页面

底部三个入口：**工作台、任务、我的**。工作台有始终清晰的“扫一扫”主按钮；无权任务不显示。助手是工作台入口和任务内的“查操作说明”，不做遮挡按钮的悬浮球。

| 页面/拟路由 | 内容 | 主动作 | 异常状态 |
|---|---|---|---|
| pages/login/index | 员工账号登录、帮助 | 登录 | 明确密码/停用/网络错误，不自动绑定客户账号 |
| pages/workbench/index | 姓名、门店、待办、最近同步时间 | 扫一扫/继续上次任务 | 过期数据加时间；无权限与零任务分开 |
| pages/tasks/index | 收货/交货/配送/农技/回访分类 | 打开任务 | 搜索、分页、失败重试、空态 |
| pages/scan/index | 扫码区域、手输码、最近识别 | 核对匹配结果 | 拒相机可手输；错误码不猜SKU |
| pages/receipt/detail | 原采购、供应商、已收/剩余、批次卡 | 核对本次收货 | 旧详情/数量变化拒绝提交 |
| pages/inventory/detail | 主单位库存、批次、货位、有效期 | 查看可交付批次 | 缺日期明确未知，不补造 |
| pages/pickup/detail | 原单与剩余物料、内部批次码 | 确认本次交货 | 售后处理中暂停；已交货只显示结果 |
| pages/delivery/detail | 本人任务、地址电话、剩余清单 | 导航/核对后签收 | 地址可读兜底；交付量变更重新核对 |
| pages/sale/index | 简洁查价、单位、购物车与原单结果 | 核对后收款登记 | 未报价/无权限/结果未知禁止再收 |
| pages/agronomy/case | 资料清单、照片、语音、问答和回访 | 采集/提交审核/记录回访 | 上传失败保留草稿；不把AI草稿当已答复 |
| pages/learning/index | 岗位SOP、案例、练习、版本 | 开始学习/请老板确认 | 过期知识标记，新旧版本不混算 |
| pages/profile/index | 员工身份、门店、网络、字号 | 查看同步/退出 | 未知交易退出前明确保护原请求 |

布局约束：一屏一个任务、一个主动作；清单用卡片而非宽表格；主数量、单位、批次名及货位同屏；完整长码支持复制，短展示不更改实际码。按钮至少48逻辑像素高，正文默认16逻辑像素，可放大；金额、数量、状态不用单一颜色表达。

## 3. 扫码必须分清业务事实

1. 普通SKU/厂商条码识别商品，不能证明具体批次、有效期或货位。
2. 内部批次标签匹配服务端真实收货批次。页面展示商品、批次、货位、原单位和可用量后才允许操作。
3. 货位码仅定位位置，不意味着该位置所有货都可以出库。
4. 提货码只定位原订单/交货任务。开单已经扣库的任务，确认提货不再出库。
5. 扫到未知码、多个同码或其他门店标签时明确阻断；支持人工搜索后选择，不自动取第一条。

普通扫码使用`uni.scanCode`；连续扫描是后续可验证优化。连续同码先锁扫描接受窗口，读数成功后振动/文字提示；同码重复事件默认合并为“又扫到同件，是否加1”，不能按相机帧数累计数量。离开页面停止相机，恢复页面重新读取任务能力。

建议新增只读解析接口`POST /api/admin/mobile/scan/resolve`，只接受`{code,purpose}`，返回`type,matches,display,requiredAction`；服务端按当前身份/门店查询。返回结果不能当提交授权。若现有标签解析服务可直接复用，只增加聚合Controller，不另建条码表。

## 4. 核心操作流程

### 收货

任务→原采购剩余→扫描商品定位行→填写实际批次、数量、采购单位、该单位成本、日期或“日期未知”→完整摘要→提交。每个批次卡显示“本次2箱＝24瓶、每箱进价、合计成本”，不要求员工理解“基准系数”。整件最小单位不得出现零碎数量，计量商品允许后台元数据规定的小数。

收货请求提交前持久化`requestKey`和不含凭据的摘要。同一请求重试不得改数量、成本、批次或商品。超时后固定原请求进入核对；查不到不能自动换号；正式重试必须复用已有收货防重能力。请求结果查询尚需补齐到移动API，不能仅靠“刷新采购列表看起来变了”。

### 交货与配送

取原单最新可交付清单→逐项核对批次与数量→服务端生成/返回核对指纹→人确认→在原订单锁下重读→确认。另一页面退货后，旧指纹失效，展示剩余物料重新核对。仍可交的部分退货订单允许交剩余，全退/取消停止，处理中售后暂停。

配送只查本人且本店已指派任务，不能单凭`order:ship`读全店地址。新增能力收敛在共享应用服务，桌面老板仍走原权限入口，不能让配送员工借手机路由取得老板权限。手机导航用坐标须明确坐标系；没有可信坐标则显示地址并交地图应用搜索，不猜坐标。签收确认不是再次销售或收款。首期不做全天后台定位。

### 移动销售

首期在收货与交付稳定后开放。报价只由ProductPricingService / PackagePricingService取得，禁止本地离线价格兜底；人工调价沿用授权和原因。服务端`pos_sale_submission`和现有UUID请求协调器作为唯一开单入口；手机、电脑同时提交同请求不重复成交。交易结果未知时保护原请求，客户端不自动重发新订单。

## 5. 现有接口与需要补齐的接口

下表的“新增”均是设计，不能按现有接口调用。实现前从当前Controller导出OpenAPI确定字段，移动端不直接调用Mapper。

| 能力 | 已有入口/服务 | 移动端增量 |
|---|---|---|
| 员工认证 | `/auth/staff/login`及当前身份接口、AuthService | 复用身份刷新与退出，无角色自注册 |
| 库存与货位 | InventoryController，`inventory:view`等真实权限 | 小屏摘要；扫码解析聚合，不增库存表 |
| 采购收货 | 既有收货应用服务、requestKey防重 | 本店待收任务/提交结果查询，复用同事务 |
| 库房交货 | PickupFulfillmentService及现有交货契约 | 绑定当前任务的读取与确认；原请求ID保留 |
| 配送 | `/api/admin/orders/{id}/ship`、`/{id}/confirm-receipt`及核对指纹 | **需补本人任务范围**和移动只读DTO，不能直接暴露全店订单列表 |
| POS | `/api/admin/orders/pos`、`/pos/submissions/{requestKey}`及取消屏障 | 复用现有开单，不另造扫码出库交易 |
| 农情与回访 | 当前“客户跟进”主要是复购估算，非农技工单 | 需新增共享农技服务模块，见共享文档 |
| 学习 | 无完整培训服务 | 先复用已发布SOP与服务案例；考试认证留第二期 |

## 6. 数据、弱网与安全

服务端是唯一事实源。读缓存显示`fetchedAt`；断网时可看旧任务但不能确认钱货。照片和语音可暂存草稿，明确“尚未上传”，不能显示“已回访”。退出、员工停用、换门店及会话变化立即隔离旧请求响应和本地草稿。

扫码/读任务可重试；收货、开单、交付确认采用原请求身份及摘要核对，不进行通用HTTP自动重试。移动端本地存储失败必须在交易发送前阻断。后台新关权限在下一真实请求生效，不等重启手机。

付款码、身份证、密码、验证码不进入日志和AI。客户电话地址仅在正在执行的本人任务可读；上传私有图片使用受限对象存储及短期访问，不返回永久公开地址。AI不能访问数据库或通过自然语言绕过员工权限。

## 7. 培训如何帮助招聘和复制能力

先建立四套基础清单：收货与批次、销售与原请求恢复、配送与部分退货、农情采集与回访。每套一页SOP、一个已审核示范案例、三道情境练习。初期用实际跟单和老板确认检查，不把答对几道题等同专业资质。

农技助理采集：作物/品种、地区、棚或露地、生育期、问题发生时间、分布、近景/全景、近期肥水药、已采取操作、联络偏好。由AI归纳、员工核对，缺关键项显示待补，不自动补猜。老板确认后形成标准答复，回访按实际发生追加结果，交接人员可看完整时间线。

每周选重复问题整理一条SOP，老板只审核差异和新知识，而非重录完整教程。新员工先跟单、再独立采集和回访，最后在授权范围执行普通任务。模型生成练习或步骤摘要可以提效，岗位权限仍由真实管理操作授予。

## 8. 实现拆分与验收

建议新目录`mini-staff/`；共享`packages/mobile-contracts/`只放纯TS合同与通用请求状态，不能放业务定价规则。开发编译使用Uni-app CLI、Vue3、TS及微信开发者工具；版本在技术验证通过时锁定，不先装一堆组件库。

| 任务 | 交付/修改范围 | 必须通过的验证 |
|---|---|---|
| E1 登录与工作台 | mini-staff登录/路由、现有员工AuthService读取 | 停用、换店、过期、旧响应不得污染；无权入口不可见且API拒绝 |
| E2 查货与扫码 | scan页面、MobileScanController、只读DTO | SKU/内部批次/货位不可混淆，同码帧去重，跨店/重码拒绝 |
| E3 收货 | receipt页面、复用收货服务、结果查询 | 分次多批次、箱瓶换算、未知日期、零/空成本拒绝、防重和未知结果 |
| E4 交货与配送 | task/detail、共享订单守卫及本人范围 | 旧清单与跨人IDOR拒绝、部分退货剩余、确认不新增钱货 |
| E5 标准服务与学习 | case/learning页面，见AI模块 | 资料缺项、人机标记、草稿/发布隔离、人工接力与跨人隐私 |
| E6 移动销售 | sale页面、原POS请求协调器 | 原价/套餐报价失效拒绝、并发库存、断网后原请求恢复，不生成第二笔 |

每项先写失败用例，再实现，再跑该模块与全套回归；最后老板/库管/销售三个最小身份真机验收并SQL只读对账。用开发者工具的模拟器不能替代真机。

体验目标（待验证，不是已测成绩）：已登录任务首屏普通网络2秒内可操作；扫码识别后的本地反馈300毫秒内；提交明确显示处理中、避免双点；读取超时10秒给重试入口，交易超时进入核对而非判断失败。至少两台安卓（含低端）、一台iPhone，正常/弱网/断网/恢复、相机拒绝、外接扫码设备另验。长单据和最小屏幕不能横向滚动才能完成主动作。

## 9. 首期不做

不做自动AI扣库存/收款/退款、后台持续定位、全功能移动财务、独立移动库存库、自动发券拉群、无限人工咨询和复杂招聘考试平台。未来需求先说明真实问题及更简单方案，不能因为有小程序就重写所有后台。
