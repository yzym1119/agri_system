# 员工小程序实施计划

> **供后续执行者：** 使用 superpowers:executing-plans 逐项执行；如用户另选代理执行方式，再采用对应技能。每项先失败用例、再最小实现、再回归。本文是待设计评审后的实施合同，本轮未执行脚手架、安装依赖或创建小程序。

**目标：** 交付与原后台共用事实账的员工微信小程序，先查货、收货、交货、配送，再接农技采集/学习与移动销售。

**架构：** 独立mini-staff，Uni-app Vue3 + TypeScript编译微信。纯TS合同与请求恢复放packages/mobile-contracts；身份和所有钱货规则仍在原Java应用服务。不能把电脑Vue页面或Element Plus直接搬到手机。

**技术：** Java17、现有Spring Boot/MyBatis-Flex/MySQL/Redis，移动Vue3/TS。新增依赖版本由真机技术验证锁定在package-lock，不使用未经验证的“最新版本”替代兼容性验证。

**设计依据：** [员工端设计](../specs/2026-10-29-员工端小程序设计与实现.md)、[共享数据与AI](../specs/2026-10-29-共享数据与AI助手实现.md)、[总体决策](../specs/2026-10-29-双端小程序-调研与总体决策.md)。

## 全局约束

- 两AppID、两前端构建、同一业务库；员工token不能进客户入口。AppSecret、密码、验证码只在安全后台或短期输入中，不进代码和本地交易摘要。
- 既有Flex连接、真实READ_COMMITTED及订单/客户/来源/库存锁序不变。提货/签收不再记钱货。
- ProductPricingService与PackagePricingService是权威报价，最小单位粒度消费后端元数据，禁止手机另维护单位白名单。
- 交易未知只核原requestKey，不自动新号重发；明确失败也沿现有POS取消屏障决定是否可更正。
- 当前工作区已有分支与测试，执行时先重读WORKING_STATE和git diff，不重建现有数据库/种子，不覆盖用户数据。

## 审查重点

1. 换员工/换店后迟到响应和旧草稿泄露或覆盖新会话。
2. 同一相机帧重复扫描被计成多件，或SKU码误作批次证据。
3. 另一终端退货后按旧清单交出已退物料。
4. 网络超时/客户端杀进程/本地存储失败后误认为未成交。
5. 普通配送员工通过修改ID读取其他人的地址，或通过AI读取整店咨询。

每项的测试归属见以下任务；不是用一个页面截图证明上述全部成立。

## 现有接口清单（2026-10-29源码核对）

| 用途 | 当前入口 | 可信事实 |
|---|---|---|
| 登录 | POST /auth/staff/login | AuthStaffController/AuthService；不得客户端自指定角色 |
| 待收/详情 | GET /api/admin/purchase/receiving-orders、/{orderId} | purchase:inbound，不要求库管取得完整采购编辑权 |
| 收货 | POST /api/admin/purchase/receipts | PurchaseController → 既有采购收货服务，原requestKey防重 |
| 提货列表 | GET /api/admin/orders/pickup/requests | order:pickup:verify，服务端校验门店 |
| 提货确认 | POST /api/admin/orders/pickup/requests/{requestId}/fulfill | PickupFulfillmentCommand：scannedCode或原分配allocationIds等；不猜新批次 |
| 配送与签收 | POST /api/admin/orders/{orderId}/ship、/{orderId}/confirm-receipt | 需移动本人任务范围；签收仍使用后端核对key |
| POS及结果 | POST /api/admin/orders/pos；GET /pos/submissions/{requestKey}；POST /pos/submissions/{requestKey}/cancel | 同一PosSaleSubmissionService，不新建收银写入口 |

路径以对应Controller为准，不能用旧OpenAPI中未列接口假装不存在；响应有裸值和包装体差异，需要逐入口解码。

## E1：身份、严格响应解码与请求恢复

**文件：** 新增`packages/mobile-contracts/src/{actor,transport,submission,uuid}.ts`及对应测试；`mini-staff/src/services/{auth,request}.ts`、`src/stores/session.ts`、`src/pages/login/index.vue`、`src/pages/workbench/index.vue`、`src/pages/tasks/index.vue`。

**接口：**

- `ActorScope = {staffId:string;storeId:string;sessionEpoch:number}`，ID用字符串避免bigint精度损失。
- `decodeResponse<T>(endpoint,response): T`按端点定义裸ID、分页或包装体；不得`response.data || response`掩盖0/空值。
- `SubmissionRecord = {schemaVersion:1;requestKey:string;scope;summary;state}`，只存有限核对摘要，不持久化可自动重发的钱货请求体。
- `submitOnce<T>(record,send): Promise<Outcome<T>>`；`lookupOriginal<T>(record,read): Promise<Outcome<T>>`。各业务通过适配器决定明确拒绝和结束屏障，禁止通用自动重试POST。

## 发布与回退

先部署向后兼容的只读/作用域能力，再部署员工体验版；服务端新写能力默认不扩大任何角色。回退保留原请求结果与业务事实，停用新页面入口而不删库。跨端请求协调、任务范围和旧请求恢复任一未通过，不能开放对应交易功能。
