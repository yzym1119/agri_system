# 员工目录可售量实现计划

目标：选择商品时看到本店、同实际出库筛选口径的可售数量；取消旧inventory汇总的第二次500行拉取。保留POS最终锁库裁决、价格入口和资金恢复，不加表、不改迁移或扣减规则。

1. 既有InventoryBatchBalanceRepository/Mapper新增按门店与当前页商品ID批量只读查询，复用实际select的余额大于预留、启用货位、有效期为空或不早于数据库今天条件。不加FOR UPDATE。按商品及原批base_unit_id分组保留单位证据；不能把不同持久单位直接相加。
2. PosCatalogApplicationService在分页与搜索共用组装后，严格解析当前员工门店，一次批量查询。目录VO扩展可售量字符串及所属门店，保留持久baseUnitName；资料缺失/单位不一致给null，不猜零。正常无正余额为零。继续白名单投影、不返回成本；当前商品查询分页实现本身已有的单位N+1不在本轮冒称解决。
3. 移动契约增加可售量/门店字段，验证原十进制字符串精度；旧响应没有字段显示待核对。员工页面明确“本店可售 N 基准单位、按主单位销售”；价格目录标签使用原pricingUnit，不把基准价标成主单位价。零量或无法核对的资料阻止加购，仍走后端真实报价。此次不添加前端最大购买量计算，避免换算舍入与多行累计形成第二套出库规则。
4. 测试先红后绿：真实SQL排除预留、昨日过期、停用货位与别店，今天有效/未知日期保留；多个商品批量与混合单位。应用验证门店缺失/越权/单位证据/无库存/不泄露成本。契约和页面验证未知不等于零、精度、无500行拉取、0量拒绝与报价/恢复回归。
5. Java17完整verify含MySQL/权限、报告门禁；共享包/员工端测试、类型与生产构建。独立审查后修复，更新当前状态、提交推GitHub现有整合分支。模拟器/真机与正式支付没有实际做则单列。

关注：边界日期使用数据库CURRENT_DATE；原批与当前基准单位ID不一致不能用同名猜测；门店为空的管理员也不能被当成全店；旧目录或查询失败不能留下可信零值；商品主单位与计价/基准单位不同必须明确。
