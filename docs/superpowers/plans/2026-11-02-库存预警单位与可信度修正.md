# 库存预警单位与可信度修正

继续清单B3时发现真实业务缺陷，优先修正后再做剩余Mapper收敛，不只移动错误代码。

## 验收目标

- 库存账仍保存基准数量；库存建议/风险中的当前数量、销售速度、已配置和推荐阈值统一为商品主单位。
- 销售行使用自身销售单位的持久直接系数换算；不同销售单位不能直接相加。单位关系缺失/无效时不猜系数。
- 保留原销售观察窗口与成交状态口径，本次不擅自将历史总销量改成净退货后销量。
- 提示读取受真实门店与租户交集限制，null门店不是绕过；库存仍由基准余额减预留产生。
- 没有可核对库存/单位证据，或销售样本不足，均不得显示正常/绿色或采纳数值；已知零余额与未知分开。
- 日期提示仍根据真实有效期，不因数量换算缺失而隐藏；数量未知显示未知。
- 不改采购、销售、退货和库存写入，不加表、模式、自动采购或新的价格来源。

## 实施顺序

1. 在随机MySQL小型测试库复现混合箱/瓶销售和预留库存的错误；固定已知零、未知换算、默认租户范围场景。
2. 增加统一库存规划只读入口，返回主单位可用量/系数与规范化销售速度；实现中显式保持门店租户交集。替代两应用服务直接依赖旧销售速度Mapper，旧入口确认无调用后移除。
3. SmartThresholdService与InventoryRiskService统一消费上述证据，保留补货公式/风险留痕；未知推荐不生成可采纳数字，风险显示单位。
4. 推荐页处理DATA_INSUFFICIENT及未知状态，禁止单条/批量采纳不可信行，展示未知量，保留原权限。
5. MySQL实际查询、应用逻辑、页面真实函数/模板回归，完整后端和前端类型构建；独立审查、更新清单、提交推送。不把自动化等同真机或原环境部署。
