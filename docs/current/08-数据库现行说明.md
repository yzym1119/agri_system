| 赊销与退款 | 原应收、明确还款分配和售后事实 | 冲欠与实还区分，来源未知不能猜零 |

## V143微信身份命名空间

customer_identity增加app_id（ASCII二进制、32字符、NOT NULL默认空串），identity_value改utf8mb4_bin，唯一键为`uniq_customer_identity_scope(identity_type,app_id,identity_value)`。旧数据空AppID是未知证据，不按当前配置回填；非微信旧身份仍空域，客户phone原索引不在本批修改。客户ID仍非空，尚不能用该表假装新客手机号/待关联流程已落地。

迁移不重写customer_id、订单、钱包、余额或身份status。当前微信仓储必须明确AppID；读取只投影授权元数据，不载入sessionKey，敏感写在原Flex连接手动绑定。身份行持久撤销版本已由V144补齐；未来后台治理仍需客户级生命周期撤销及原子审计/防重，不能以修改名称/备注或只改身份状态冒充完整安全关联。


## V144身份行持久撤销版本

仅既有customer_identity新增auth_version BIGINT NOT NULL DEFAULT 1。旧行初始化1，不改身份归属、状态、AppID、凭据或客户/钱货。字段不能由页面任意写入：仓储以实际读取版本校验、条件更新，customer_id/identity_type/app_id/identity_value/status改变才递增，凭据刷新或同值保存保持版本；丢失/陈旧版本与溢出拒绝。普通登录不因刷新sessionKey撤销其他设备。

微信token保存登录时版本，每次本人资源读取当前行核对，旧无版本token不得从当前值补齐；停用复启、关联改出改回不会恢复旧token。保持同Flex连接与凭据不读不日志，原外层事务回滚则版本和身份修改一起回滚。任何未来治理入口均须调用该仓储，并在同事务补治理请求/核验审计；本字段不能代替该审计，也不能代替客户主档停用复启的客户级纪元。无治理表/后台操作入口、首次授权或开户在本轮新增。


## C0-B②短时授权不建业务档案

本批无新表/字段或数据库迁移，最高版本仍V144。新微信的PHONE_REQUIRED/PHONE_VERIFIED只存在SaToken短时会话，最多原600秒，不存SessionKey/wxCode；号码核验仅保存内部证据、界面脱敏，不作为customer_id。未创建客户/钱包/身份映射，不落历史业务归属。后续持久待关联与开户仍需核现结构是否能承担请求防重/审计，不能用临时会话替代业务审计。微信平台令牌继续使用唯一原Redis缓存键wechat:access_token:{AppID}，通知与手机号共享。


## V145初次开户与关联申请（源码验证通过，原库未升级）

新增唯一一张customer_identity_enrollment，不复制客户、订单、钱包。sys_operation_log缺请求唯一键/待办/固定结果；customer_identity又要求已有客户，二者无法直接承担未建客户申请。字段分为原request_key/fingerprint/app_id/open_id/phone/display_name/verified_at、当前active_subject、status/review_reason、完成customer_id/identity_id/identity_auth_version快照，以及独立决定request_key/fingerprint/reviewed_by/verification_method/reason/time。

唯一索引为`uniq_identity_enrollment_request`、`uniq_identity_enrollment_active`（允许NULL）、`uniq_identity_enrollment_decision`；队列与主体索引为`idx_identity_enrollment_queue(status,id)`、`idx_identity_enrollment_subject(app_id,open_id,id)`。拒绝仅释放当前锚，不删旧请求；旧UUID恢复在upsert前后都优先原请求，只缺原UUID才定位当前锚，再按PRIMARY锁。PROCESSING仅事务内，正式结果CREATED/REVIEW_REQUIRED/LINKED/REJECTED；查询无记录为UNKNOWN，不推断未成交/未创建。

V145另在现sys_menu加入identity query/bind两个权限，不自动授角色；不改手机号唯一索引、不回填未知AppID、不改客户/资金旧事实。原开发库未升级。本批最终真实MySQL/authority完整1099项通过。query菜单为核验页面、bind为其独立操作，仍须原customer:query。显式结束申请复用一次最终REJECT，不加取消表/字段。新大陆手机统一11位，历史别名只读查重不批量修改；旧值REPLACE查询最多检测2条，会扫描联系方式，当前小门店规模可接受，数据量增长后量测再定索引，不提前增字段。
