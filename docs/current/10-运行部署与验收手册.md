# 运行部署与验收手册

版本V1.0，2026-11-08。整合现有操作入口，不代表已部署或实测所有设备。源码启动参数以[根README](../../README.md)、各工程锁文件及目标环境实际配置为准。

## 环境与启动

1. 确认工作目录、分支、提交及未提交改动，其他AI新提交必须核对后再报完成度。Java17、MySQL/Redis沿工程配置；不把环境变量或密钥写入报告。
2. 先查目标库Flyway历史与备份。已有库不导入ddl/schema.sql，不改已执行迁移。新随机隔离库才可用于虚构业务联调，原库清理须明确授权。
3. 后端按根README的模块启动；不能用旧固定JAR验证新增API。前端服务地址、后端提交、数据库迁移和构建提交写入验收记录。
4. 管理端操作参考admin-web/package.json；员工端参考mini-staff/package.json。客户端工程尚无，不提供不存在的可运行启动命令。

员工端已存在的验证命令（仓库根执行）：

```bash
npm --prefix packages/mobile-contracts test
npm --prefix mini-staff test
npm --prefix mini-staff run type-check

```

```bash
./mvnw -B -Dmysql.it=true -Dauthority.mysql.it=true clean verify
```

不得将这些命令连接生产数据。数量、报告数和跳过数记录本次实际输出，不复制旧983/111/59数字。类型/构建通过不证明真实HTTP或微信手机行为。

## 微信与三端验收

员工dev导入mini-staff/dist/dev/mp-weixin，生产包为dist/build/mp-weixin；本机联调使用现dev脚本。AppID按环境配置，秘密仅后端持有。游客/测试号不是正式身份联调；临时放宽域名检查只限明确授权测试工程，结束恢复，正式验证HTTPS/证书/域名。手机号授权和普通微信登录是不同凭证。

验收按[员工手册](06-员工端设计与实施手册.md)A/B项、[客户手册](07-客户端设计与实施手册.md)C项及[后台协同](03-后台管理与三端协同设计.md)ADM项执行。至少包含收银/库管/配送/无权/别店/停用身份，后台同orderId/receiptId/请求身份及原批次流水核对。

每条记录：测试编号、提交/产物、后端/库/迁移、角色门店、设备/微信基础库、输入/故障点、原请求和单据、预期实际、脱敏API/只读SQL、截图、通过/失败/未测/范围外、复测。真实收付与虚构provider证据分开；不使用真实客户资料作随意测试。

## 本人订单权限与岗位验收（V142）

1. 使用匹配本次提交的后端与员工生产包；目标库先按既有安全迁移流程升级至V142，保留V140等已执行历史文件及请求屏障。V142只加`sys_menu.permission=order:own:query`，不新建业务表、不改员工订单归属、不自动增加角色授权。
2. 实际管理员进入后台角色管理，明确给销售岗位勾选“本人订单查询”。已有`pos:order:create`、整店`order:query`或本机收藏都不代替该权限。库管是否需要由管理员按职责决定，不写死角色ID。
3. 员工回工作台刷新身份，看到“本人订单”；可设为手机常用。未授权、撤权、角色停用或离职必须服务端拒绝列表与详情，不能只靠隐藏按钮。无门店不放宽到全店。
4. 在隔离测试环境准备同店员工A/B、别店员工C、历史缺staff_id及超过20条的已知订单；A只查本店原staff_id=A的POS，改URL访问B/C或缺员工的单须拒绝，伪造staffId/storeId查询参数不能扩大范围。验证跨页无重复/遗漏、含首尾日期和状态过滤。
5. 后台打开同orderId，对比原净应结算、开单已收、原赊销、累计实还、冲欠、退已收、当前欠款及原商品/套餐快照。至少包含现金、赊销、部分退货和缺历史资料；未知明确“待核对”，不写0。没有配送记录不等于已交货。本人订单页没有退款、改派、签收或收款动作。
6. Android/iPhone分别核对长订单号、长套餐名、日期选择、分页/重试、前后台、退出换人、迟到失败。保存设备/包/服务/迁移版本、脱敏HTTP及同单字段证据；当前自动测试和编译不替代这些实操。

关闭入口优先撤回该独立授权并回退匹配程序包；保留已迁移权限项、历史订单及审计，不删表或改旧迁移作回退。本轮未对原开发库/现有运行服务执行升级，以上是部署操作合同，实际执行须记录目标环境。

## 整单备货岗位验收

原`order:pickup:verify`即可读整单清单，无新迁移或授权；使用匹配本轮提交的后端与员工包，不能把旧服务404当当前功能通过。目标环境升级另行记录，本轮没有替换原服务。

- 隔离环境准备同单25项以上物料、多批次/多货位及一项暂停，清单必须全量；备好计数与原待交/已交计数分开，勾完不显示整单已交。只看未备好不能漏暂停项，原逐项交货仍需最新预览和实际交付确认。
- 同身份离页/前后台/杀进程后先读真实接口再恢复进度；数量/批次变更、售后暂停再撤销、部分退款、取消/完成各核一次，相关旧勾选不能复活。换员工或门店不得恢复他人记录；变更前后保留API/原分配与最少缓存字段证据。
- Android/iPhone各实际扫描同批次多货位与重复编码：展示全部匹配候选，扫码自动勾选/自动交货均0。拒相机时手动商品/批次/货位查询可用。
- 写满/损坏/读取失败或其他页面替换缓存时，不伪装保存成功；清除备货进度只删个人preparation记录，不删原pending。模拟原交货丢响应后，优先核原请求，整单备货不能遮掉其未知状态。
- 对同一原订单交货前后核原SALE/RETURN与资金流水，备货勾选新增钱货0，原确认也不得再扣一次库存。两员工同时处理的重复搬货仍按岗位约定规避，当前没有任务认领/排他功能。

自动用例只证明代码路径，不代替真实手机布局、扫码、后台杀进程及岗位耗时/遗漏观察。配送待备货不是库房提货的同一对象，未新增入口或伪造签收完成。

## 异常与回退

- POS未知固定UUID查询或取得取消屏障；收货未知固定原摘要；提货/配送未知重读原事实。不能删本地记录解冻或换新号重收。
- 财务先核原订单/来源、实还/冲欠/退已收；库存先核原批次/货位/单位与SALE-RETURN，不猜未知为0。
- 权限或改派异常先核服务端真实身份/角色/指派版本，不能给普通员工扩大权限以绕403。
- 发布回退保留请求屏障、订单、支付、售后、库存流水；关闭新入口也保留原结果查询/退款处置。程序与迁移兼容先查，不执行删表“回退”。
- 特定旧升级步骤见[runbooks](../runbooks/)，只对匹配版本和经核验环境使用；不得把历史切换模式恢复成当前可写链路。

当前未提供面向生产服务器的完整运维SLA、恢复演练结果或正式微信发布记录；这些列入完善清单，条件具备后补证据，不用文档文字冒充已完成。
