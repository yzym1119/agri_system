## 4. 数据与接口不可改变的边界

- 同一客户主档、商品/单位、订单、原配送和批次账，不为手机新建镜像业务系统。
- 库存读取需区分inventory投影与实际可出库批次；已知有效期参与FEFO，未知不造日期。库存移动保留原单位与来源，提货确认不再次SALE。

## 5. 关键操作流程

### 客户治理

后台待关联/重复线索→两档案对比与核验→固定源/目标和影响预览→锁下重查资格→执行一次→查原结果/审计。仅同人且无历史业务空壳可首期合并；双方已有业务明确阻断转专项核账，不删除原档案或改旧单客户ID。解除/合并后使旧会话失效。

### 手机销售到库房

员工自己登录→单品/套餐后端报价→原POS开单→后台同单可查→按实际交付方式进入原任务/配送→手机看整单实际物料→准备勾选→最新余量与原指纹确认实际交货→后台核对剩余。

多人可同时看到任务不等于系统已实现认领；首期明确一人作业约定，持久认领/移交若需要须另设计。防重提交只能防重复写钱货，不能防两个员工实际搬同一批货。

### 农技服务（未来）

客户确认资料→同case分配给员工采集→标准知识可直接服务/复杂问题进老板审核→回复→真实回访→经同意脱敏形成知识草稿。知识发布和专业个案审核分别授权，不让模型或普通员工自称老板批准。
