# V136—V138升级与回退约束

V136删除独立线上价，V137删除旧绩效表，V138增加批次余额门店/商品索引及调整钱包验证码表排序规则。它们已在本机开发库执行，原SQL与Flyway校验值必须保持，不得以repair或修改已执行脚本掩盖差异。

## 执行入口与停写

1. 先明确目标数据库、当前版本、实际运行包和全部写入进程；原本机各隔离预览是不同环境，不得混用数据库或一起停掉。
2. 停止目标库全部旧应用和外部写入，再做完整结构/数据/触发器备份，并验证可恢复。结构快照`ddl/schema.sql`不是数据备份。
3. 使用包含本轮`MigrationSafetyConfiguration`与`LegacyPerformanceDropGuard`的新包执行Spring Boot迁移。Boot收集Callback bean；独立Flyway调用必须显式注册同一Callback。直接运行V137 SQL、旧包或未注册Callback的Flyway不受保护，不能作为本次升级入口。
4. 保护会在迁移开始前、以及V137执行前检查：目标至少V137、V137尚未成功且旧表非空时拒绝；无法读取时也拒绝。此检查不替代停止旧写入，不能声称防住并发旧进程写入。
5. 如发现非空旧绩效，先保留原库和备份，由业务确认归档及历史使用需求。**不要清空表来通过检查，也不要补造迁移/归档事实。** 本轮不提供自动搬迁或删除历史功能。

## 升级与核对

- 空旧表才允许继续；V136之后旧包仍映射`online_price`，因此不得让旧进程继续读写、做滚动混跑或直接回退旧包。
- 迁移成功后核对：最高V138、失败记录0、商品无`online_price`、旧绩效表不存在、`idx_ibb_store_product`前导列依次为store_id/product_id、wallet_auth_code为utf8mb4_unicode_ci。
- 再通过新包检查商品创建/更新/读取与统一报价、采购创建金额、库存及权限。金额修复只作用新建采购计划，不回算历史采购或实际库存成本。
- 本轮自动测试仅在新建随机MySQL库验证V135升级、非空拒绝、后置条件与成功重放；没有对原开发库或原预览执行迁移。

## 已升级或失败时

- 已到V138且旧表已删除的库，保护不会恢复未知旧数据。仅凭当前表不存在，不能证明删除前为空。
- MySQL DDL并非整个迁移链原子回滚；中途失败时可能已有删列/索引生效。保留失败现场并按实际元数据和备份评审，不自动repair、补空表、补NULL字段或再次执行全部SQL。
- 回退旧包必须同时恢复**相匹配的迁移前数据库备份**，评估备份后的新增交易如何保留。不能只切换JAR。缺少可靠备份时，不提供“猜测恢复”，优先评审兼容新结构的修复包。

当前本机开发库已到V138，独立员工验收库仍V135；本轮只核实状态和校验值，没有升级任何原运行环境。发布前仍须明确账号、权限及实际目标，不能因为本地测试通过就认定正式上线。
