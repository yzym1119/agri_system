# AI 生成后端项目限制文档（优化版）

## 1. 项目目标

构建高性能、可维护、可扩展的农资行业进销存系统，确保 AI
多轮生成时一致、无幻觉、无遗漏，保证长期可扩展性。

## 2. 架构与设计规范

### 2.1 DDD‑Lite 分层规范

所有后端模块必须遵循以下分层结构： -
**api/controller**：只负责参数校验、调用应用服务、返回 DTO。 -
**application/service**：编排业务流程，不写领域规则。 -
**domain/model/entity/value-object**：核心业务规则、聚合根、领域事件。 -
**domain/service**：不能归属实体的业务规则。 -
**infrastructure/repository**：数据持久化（MyBatis‑Flex）、第三方接口。

controller 禁止出现任何业务逻辑。

### 2.2 模块结构规范

每个功能都是独立模块，如： - product - inventory - order - customer -
store - warehouse - staff - performance - promotion -
notification（必要时）

模块必须实现高内聚低耦合。

------------------------------------------------------------------------

## 3. 数据模型与数据库规范

### 3.1 数据库设计

-   使用 MySQL 8.x。
-   所有模块涉及到数据库的任务必须提供：
    -   **完整 DDL（MySQL）**\
    -   **Flyway 迁移脚本 `V{n}__desc.sql`**\
    -   字段注释、索引、外键说明

### 3.2 无幻觉约束

-   禁止生成未在任务中定义的字段/枚举/表。
-   若业务需要新增字段，必须在文档中：
    1.  明确指出要新增\
    2.  解释原因\
    3.  等待人工确认后再继续

------------------------------------------------------------------------

## 4. API 与开放接口

### 4.1 OpenAPI / Swagger

所有 Controller 必须： - 完整注解（字段、鉴权、响应、错误码） - 自动生成
openapi.yaml

### 4.2 API 规范

-   接口必须遵循 RESTful 风格。
-   所有写操作必须具备幂等性（如：订单创建的 `Idempotency-Key`）。

------------------------------------------------------------------------

## 5. 鉴权与安全

统一使用 **Sa‑Token**： - 角色：ADMIN / MANAGER / STAFF / CUSTOMER -
权限：按资源定义（product:edit、inventory:adjust...） -
高危操作必须有操作日志（库存调整、退款、价格变更）

------------------------------------------------------------------------

## 6. 事务、并发、幂等

### 6.1 事务边界

-   所有写操作必须说明事务边界（@Transactional）
-   跨模块写操作需要：
    -   事务一致性说明
    -   或补偿逻辑
    -   或可靠消息机制

### 6.2 并发控制

关键逻辑（库存扣减、订单支付）必须保持强一致性，示例： - 行级锁（select
for update） - CAS 重试 - 乐观锁 version 字段

------------------------------------------------------------------------

## 7. 日志与链路追踪

所有模块必须支持： - 请求日志（traceId） - 业务关键点日志 - 集成
OpenTelemetry（最少提供 starter & 配置示例）

------------------------------------------------------------------------

## 8. 错误码规范

所有模块必须输出： - 统一错误码文档\
- 错误结构 `{code, message, data, requestId}`

错误码格式规范： - 400xxx 参数错误 - 401xxx 鉴权相关 - 404xxx
资源不存在 - 409xxx 并发冲突 - 500xxx 系统错误 - 600xxx
业务错误（如库存不足）

------------------------------------------------------------------------

## 9. 配置文件

必须提供： - application-dev.yml - application-test.yml -
application-prod.yml

禁止在配置文件写入真实密码，使用占位符：

    spring.datasource.password=${DB_PASSWORD}

------------------------------------------------------------------------

## 10. 容器化部署

每个模块必须提供： - Dockerfile - docker-compose.yml（包含
MySQL、Redis、App） - GitHub Actions CI/CD
pipeline（build‑test‑image‑push）

------------------------------------------------------------------------

## 11. 代码质量

必须包含： - SpotBugs - Checkstyle/PMD - Google Java Format -
单元测试（JUnit） - 集成测试（SpringBootTest）

任何提交必须包含测试。

------------------------------------------------------------------------

## 12. 文档要求

每个模块必须提供 README： - 功能说明 - API 列表 - DB 迁移说明 -
本地运行说明 - 部署说明 - 已知问题 - TODO

------------------------------------------------------------------------

## 13. 人工审核点（AI 禁止自动执行）

以下变更必须经人工确认： - 修改主键、外键 - 删除表/字段 - 价格相关逻辑 -
佣金/绩效公式 - 第三方服务账号配置

------------------------------------------------------------------------

## 14. 可验证交付物清单

每个任务必须包含： 1. Controller + Service + Domain + Repository 代码\
2. OpenAPI 文档\
3. 单元测试\
4. 集成测试\
5. DDL + Flyway 脚本\
6. README\
7. Dockerfile\
8. 本地验证步骤（curl 示例）

未满足全部交付物视为失败。

------------------------------------------------------------------------
