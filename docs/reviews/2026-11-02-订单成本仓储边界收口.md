# 订单成本仓储边界收口

日期：2026-11-02。清单B3应用层直接Mapper依赖的最后一个子项。

## 影响与方案

OrderCostAllocationService原直接使用OrderItemMapper读取订单行，并在实际出库分配确定后更新base_unit_id、base_quantity、unit_cost展示快照。真实调用来自InventoryLedgerService.outbound：先核对并锁原订单明细、扣减库存、保存批次分配，再刷新展示快照。后续历史成本展示的原定向写入仍由既有出库链处理。本轮未发现新的成本公式缺陷，不为分层更改钱货或成本口径。

采用最小方案：复用已有OrderItemRepository.findById，在同一仓储增加updateBatchCostSnapshot，基础设施实现仅委托原Mapper方法。没有再建成本仓储、表或通用模块。读取仍为同一selectOneById，更新SQL原样保留，只改三列，不能用save/整行update覆盖历史成交、折扣或成本。

保留原ACTUAL/历史估算/未知分类、基准加权成本八位精度、无持久基准单位跳过、零成本展示为空以及原事务注解、Flex数据源和锁序。仓储实现不另开事务，不改变原锁获取顺序。修正服务注释中的旧SKU激活措辞，不引入模式。
