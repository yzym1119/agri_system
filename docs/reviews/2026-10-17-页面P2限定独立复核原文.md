## 当前结论

未发现新增 P1。复核发现的 2 项 P2 会话失败边界均已由实施者补修，本次限定独立复验通过；在所列范围内无剩余 P1/P2 阻断。下文保留原发现和实际复现，修后关闭证据见末尾。

### P2-1：旧请求的 401 在共享拦截器先清除了新员工会话

位置：`admin-web/src/utils/request.ts` 原业务 401/10003 与 HTTP 401 分支；影响本轮 `store/user.ts` 与 `store/permission.ts` 的过期请求防护完整性。

`fetchUserInfo` 的 token/请求序号保护在 API Promise 返回后生效，共享响应拦截器却先无条件 reset 当前员工及跳转登录。实际执行原拦截器、传入旧 Authorization，保持 store 为新员工 token：业务 401 与 HTTP 401 均将新 token 清为空。输出分别为 `{"case":"旧身份请求业务401晚到","newSessionToken":"","resets":1}`、`{"case":"旧菜单请求HTTP401晚到","newSessionToken":"","resets":2}`。

应在共享失效处理时核对响应原请求携带的 Authorization 与当前 token，仅当前会话对应的失效响应才能清理。复核期间已看到实施者加入 `expireCurrentSession`，最终测试待追加。

### P2-2：当前身份请求失败会被路由误当成过期导航而停留原页

位置：`admin-web/src/router/index.ts` 原 96-100 行，与 `admin-web/src/store/user.ts` 原 57-65 行组合。

当前 `fetchUserInfo` 网络失败会先清 token/权限再抛出，路由 catch 随后比较原 token，得到 `isCurrent()===false`，只调用 `next(false)`，遗漏登录跳转。用真实 store 与真实 guard 联合执行，输出 `{"case":"当前身份查询网络失败","token":"","next":[false]}`。原业务页面及数据停留，当前失败的错误提示和登录跳转未执行。应区分同一导航自行清空会话的失败与已经出现新会话的晚到失败。

## 已核对符合的范围

- 路由每次业务页进入均读当前身份和菜单；菜单响应使用本轮导航与 token 校验；权限或菜单变化后先删除旧动态路由再重建并重新匹配。
- 权限指令只读 permission store，空权限不再回退持久化 userInfo；watchEffect 可在权限变化时更新已有按钮并在卸载清理。
- 无 notification:query 不显示通知入口、不请求未读数；失权清空旧计数，轮询不发请求。
- ShipDialog 挂载不查员工；只在打开 local 弹窗且有 staff:list 时查员工；关窗、换订单、换模式、权限变化更新 formSession 并清列表，旧响应不回填新弹窗。
- 状态 8 列表严格判断后端 hasReturnableItems===true，缺失标记不从前三行摘要或金额猜测；非状态 8 入口行为沿用原规则。
- queryOrderPage 仅汇总本页状态 8 的 ID，整批调用一次 findOrderIdsWithReturnableItems；本轮新增查询没有在 VO 逐行转换内再查一次。已有分页商品概览等旧查询不在本轮改造范围。
- 剩余物料 SQL 直接读取整单 order_item，含第四行与零元行；按 after_sales_item.quantity 累计占用，after_sales.status<>90，与详情 loadOrderItemRefundAggregates 只排除驳回的口径一致。父售后 order_id 和物料 order_id 相等，避免异单错误明细占用；售后 status 与数量数据库均 NOT NULL。返回 DISTINCT 订单 ID，一条参数化 SQL，空集合不执行 SQL。
- 未新增表、持久化字段或迁移；没有更改资金、库存和履约写事务。

## 两项 P2 修后关闭结论

实施者将业务 401/10003 和 HTTP 401 汇入 `expireCurrentSession`，从原请求 headers 读取 Authorization（兼容 AxiosHeaders.get 与普通对象），仅原请求令牌与当前 store.token 相等时 reset 和跳登录。旧请求仍按失败返回，不会把旧失败改成成功。
