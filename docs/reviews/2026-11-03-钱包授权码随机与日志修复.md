# 钱包授权码随机与日志修复

对应上一轮剩余依赖核查的具体发现，未展开钱包结构重构。

## 修改范围

WalletClientController真实调用的generateAndStoreWalletAuthCode原使用Math.random生成六位码，且info输出原码。现复用静态SecureRandom，nextInt(1_000_000)并按Locale.ROOT补齐六位，保持000000—999999范围及前导零格式。安全随机来源通过生产代码审查确认，不用统计“看起来随机”冒充密码学验证。

移除生成日志与关联成功/失败日志中的原码。关联方法当前主源码无调用方，本次一并清理其泄露风险，不宣称真实业务已执行此方法。SQL、数据字段、原返回值、有效期、客户/订单/金额绑定、验证码条件核销与原事务全部保持不变。无新表、模式、验证码第二来源或独立写事务。

## 验证

- 新增WalletAuthCodePrivacyTest两项，原实现失败2、错误0：真实内存数据库保存虚构绑定/金额/状态/有效期后捕获原生产日志发现原码；关联两分支使用JDBC替身，捕获原生产日志同样失败。断言消息不展示授权码。
- 修后同两项通过。生成用例覆盖六位ASCII格式、原返回与保存值一致、客户/订单/金额/状态及五分钟有效期。没有用随机抽样不重复率证明安全。
- 最终完整Java17 `mvn clean verify -B -Dmysql.it=true -Dauthority.mysql.it=true` 成功，报告136份、904项，失败0、错误0、跳过0；真实MySQL与权限并发测试开启。报告门禁及diff检查通过。
- 独立审查无重要问题。可选建议要求日志测试保留INFO/WARN数量，此处不强制：目标是原码不进入日志，完全取消这些日志也是合法实现，不把日志条数锁成产品契约。
