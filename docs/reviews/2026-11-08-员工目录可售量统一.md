# 员工商品目录本店可售量统一

日期：2026-11-08。基线：codex/staff-unified-review 的 69b80ad。

## 问题与范围

员工选货原来额外读取最多 500 行库存汇总；该汇总不等于实际出库可用批次，过期、停用货位和预留量会造成偏差。商品数量较多时还可能遗漏库存。

本轮只修改 POS 只读商品目录、批次余额只读查询、共享移动契约和员工选货页。不改数据库结构、库存写入、事务锁、报价及收款流程。商品主档仍全局共享，目录可售量绑定当前员工真实门店，无绑定门店时拒绝读取。

## 实现

- 对目录当前页商品 ID 做一次批量查询，条件与正式出库一致：启用货位、余额大于预留、日期未知或有效期不早于数据库当天。按原批次基准单位分组。
- 目录只在唯一有效基准单位 ID、名称及系数 1 均明确，且全部可售余额的原单位一致时返回数量；无余额返回 0，单位事实缺失或不一致返回未知。库存字段使用十进制字符串，带门店 ID，不暴露进价。
- 员工页移除单独的 500 行库存读取；显示本店可售数量及基准单位，销售单位另列。已知零值、单位或门店待核对时阻止选择和报价。
- 刷新失效旧搜索和数量面板，保留关键词重新搜索；旧响应不能回填刷新前可售量。独立审查发现并修复此问题，新增回归修前失败、修后通过。

## 边界与下一步

本轮未部署原开发库，未操作真实资金，未做微信手机或整合界面的逐页模拟器验收。不宣称全系统无问题。可售量是读取时快照，不预留库存、不保证后续成交；出库仍以原后端锁下校验为准。仅新增的可售量查询按页批量读取，商品原有单位加载的 N+1 未在本轮处理。
