## 结论

价格维护收口到商品档案：基准单位零售价、可选会员价、最低价提醒。所有销售单位由后端使用持久化换算系数报价。历史多维策略和独立线上价退出当前报价链路，未增加表或数据库字段。

本次解决的是单品销售定价、人工议价和手工整单优惠；优惠券及钱包支付沿用现有业务。套餐档案保留，套餐收银暂时停用，避免旧套餐标价与拆分收款不一致。套餐独立定价应作为后续明确需求处理，不代表本轮已经完成。

## 为什么需要这次修改

原系统存在商品基础价、多维策略与前端回退三套计算来源。门店、会员等级、渠道、有效期、主辅单位优先级叠加，缺少稳定可解释的经营规则。实测第三单位会错误使用主辅比例，最低价被当作销售价兜底，底价未同步换算，报价故障仍能使用前端价开单。

采用现有商品字段和 product_unit 已能解决小门店业务，不需要新的价格表、价格平台、模式开关或审批流。

## 当前经营规则

| 设置/操作 | 当前含义 |
| --- | --- |
| 零售价 | 元/持久化基准单位；缺少有效零售价不能销售 |
| 会员价 | 元/同一基准单位；0或空表示使用零售价；不区分会员等级 |
| 最低价 | 元/同一基准单位；仅用于提醒与授权，不参与售价兜底 |
| 单位换算 | 例如1箱3瓶、1件12瓶，10元/瓶分别报30元/箱、120元/件 |
| 线上销售 | 与门店同价，实际客户档案决定是否使用有效会员价 |
| 人工单价议价 | 当前员工具有销售议价权限，填写原因；保存标准价、成交价、价差及员工 |
| 整单手工优惠 | 使用同一议价权限；优惠金额与原因保存到订单 |
| 报价失败/变化 | 整单拒绝，要求重新报价，不留下收款或库存扣减 |

商品维护禁止会员价高于零售价、最低价高于零售价或会员价。所有金额按分保存，明细金额先舍入再汇总。普通收银员无需议价权限即可获取标准报价和开单；默认只给超管销售议价权限，其他角色通过现有角色管理分配。

前端移除商品规则匹配及价格换算。切换客户或销售单位重新报价，过期会员按普通价格。异步返回不会恢复已删除/清空商品；恢复挂单时标准报价不变就保留已谈成交价，报价变化会明确提示重新确认。

## 数据及迁移
