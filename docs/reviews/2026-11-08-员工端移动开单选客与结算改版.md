# 员工端移动开单选客与结算改版

## 范围与业务价值

承接员工端重新设计阶段2，基线28eb37e，沿codex/staff-experience-redesign继续。原先选商品、购物清单和全部结算字段堆在一个长页，客户需要手填编号。本轮复用既有客户列表接口，按姓名或手机号找在用客户，核对后选入；不新增表、后端接口或权限。客户沿用已有共享档案可见范围，不声称只查本店客户，不从手机传入门店扩大或猜配范围。

## 改动

- 销售页按“选择商品→核对客户与结算”两阶段组织；商品卡、数量、购物清单、客户、收款与交货分层，继承公共蓝绿色和手机触控规范。
- 商品主列表显示目录价，加入仍从后端取真实报价。选择商品后定位数量区；选购阶段底部常驻清单金额和下一步按钮，避免商品多时滚到底才能结算。数量规则、实际金额及报价失败拒绝保留。
- customers服务仅在真实当前会话有customer:query或*时允许查询，status=1、pageSize=20；纯数字作为phone，否则name。ID沿用共享Long校验，响应停用/错误形状/非安全数字拒绝；结果只留ID/姓名/电话，不缓存钱包资料。查询需主动触发，手机号或名字不写本机存储。
- 选客限本次有效结果，修改关键词立即清旧结果并失效在途请求；隐藏、换会话及切页面的晚到结果拒收。没有查询权限时显示说明，可散客现金销售，不自动扩权。
- 选中或取消客户均更新原customerId并触发真实重新报价；重报价期间禁止选购、加入、移除清单，避免慢响应覆盖新清单。并修复基线已存在的“旧行重报价失败后新行覆盖整单客户指纹”：先完成旧行重新报价，本次添加结束，用户再次添加才加入新行。重新报价失败不能成交；货款与赊销都仍调用原submitSale/V133请求恢复，结果未知进入原核对页。
- 结算区明确“确认已收现金并开单”或“确认赊销并开单”，用户填写收货人/电话/地址，后端成交金额仍权威；成功展示订单编号。没有引入微信付款或钱包资金新入口。
