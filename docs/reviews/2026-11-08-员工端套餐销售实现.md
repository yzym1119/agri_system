# 员工端套餐销售（含单品混单）实现记录

日期：2026-11-08
基线：`codex/staff-unified-review@2cf6e9a`
依据：`docs/superpowers/specs/2026-11-08-员工端小程序详细设计与实施手册.md` 补充设计 V2.1「手机套餐销售」
范围：`packages/mobile-contracts`、`mini-staff` 两个工程；**后端零改动、零 DDL、零数据变更**

## 一、为什么先做这一项

V2.1 把员工主线调整为「①整合验收 → ②套餐销售 → ③多货清单 → ④本人订单 → ⑤认领/移交」。①需要真机、六类账号与独立库，属于环境与人工验收；②是纯工程增量且依赖已就绪：

- `OrderItemDTO` 已经支持 `itemType=2 / packageId / packageQuoteId / quantity`，后端 `expandPackageSales` 负责重报价、校验指纹、展开物料、按整单分摊并锁套餐主档；
- 套餐报价接口 `GET /api/admin/product-packages/{id}/price-quote` 的权限是 `package:query` **OR** `pos:order:create`，员工端本来就有权调用；
- 套餐目录 `GET /api/admin/pos/catalog/packages` 已按 `scopedStore()` 限定本店，并返回「本店可售套数」（子商品可用量整除取小，`ProductPackageApplicationService.calculatePackageStocks`）。

也就是说，缺的只是手机端：目录、报价、套数、混单和命令组装。

## 二、改了什么

### 2.1 契约层（`packages/mobile-contracts/src/sale.ts`）

| 新增 | 说明 |
| --- | --- |
| `PackageMaterial` / `PosPackage` / `decodePackages` | 套餐目录只取 id/编码/名称/每套价/组成/本店可售套数；`stock` 缺失或非法一律 `null`（**未知不当 0**），有值则向下取整 |
| `PackageQuote` / `decodePackageQuote` | 校验 `quoteId`、`packageId` 与请求一致、`quantity` 回显一致、金额为两位十进制；不符即 `PACKAGE_QUOTE_INVALID` |
| `PackageSaleLine` + `isPackageLine` | `SaleLine` 改为「单品 | 套餐」联合类型；套餐行必带 `packageId`、`packageQuoteId`、套数与每套价，并保留 `materials` 供页面核对 |
| `assertSaleLine` | 摘要与提交命令共用的行校验，避免「摘要过了、命令没校验」的缝隙 |

命令组装（`buildSaleCommand`）：

```
单品 → { productId, itemType:1, quantity, unit, quotedUnitPrice }
套餐 → { packageId, itemType:2, quantity(套), unit:'套', quotedUnitPrice, packageQuoteId }
```

套餐行**不带 `productId`**（后端会以「套餐行只能指定套餐ID」拒绝），也不带任何物料行与分摊金额——与后端 E2E 夹具 `packageSale()` 完全同形（那里同样传 `unit:"套"`）。

### 2.2 本机恢复摘要（`submission.ts`）

套餐没有 `productId`，而原摘要校验要求 `productId` 必须是正长整型。改为：`productId` 与 `packageId` **恰有一个**（都为 null 或都有都拒绝），类型放宽为 `string | null`。摘要仍是本机恢复线索，不参与成交金额；历史记录（有 `productId`、`packageId:null`）继续有效，schema 版本不变。

恢复页（`pages/recovery/index.vue`）明细行相应改为「套餐 <id>」或「商品 <id>」，不再把套餐显示成商品。

### 2.3 服务层（`mini-staff/src/services/sale.ts`）

- `readPackages(epoch)`：`/api/admin/pos/catalog/packages?pageNum=1&pageSize=200`，不传 `storeId`（后端按当前员工门店解析）。
- `quotePackage(packageId, 套数, epoch, customerId)`：带 `storeId`、`customerId`、`quantity`，返回 `quoteId` 作唯一指纹；不传 `dealUnitPrice`（员工端无改价）。

### 2.4 开单页（`pages/sale/index.vue`）

- 商品 / 套餐两个 `.tab` 分段；切换时清空关键词与提示，避免「没有匹配的商品」留在套餐页；套餐关键词**本地过滤**（该接口没有关键词参数，页面只加载一页 200 条），因此套餐模式下不再触发商品搜索请求。
- 套餐卡：名称、编码、每套价、`本店可售 N 套`、`含 复合肥 2袋 …`（组成来自目录）。
- 可售套数 `0` → 拒绝加入并说明「请先收货或调拨」；`null`（未知）→ 拒绝并说明「可售套数待核对，请先在后台确认套餐配置」。两条文案分开，不把未知说成没货。
- 套数面板：`−/输入/+`，只接受 `1..9999` 正整数；半套直接拦在报价之前。
- 换客户：单品与套餐**一起**重报价，套餐用新客户上下文重取并替换 `packageQuoteId`（会员价变化即旧指纹作废）；慢请求按序号丢弃。
- 报价期间客户变更 → 放弃加入并提示，不把零售价记成会员价（与单品同一条守卫）。
- 清单按行显示「套餐」chip、`N 套 · 每套 ¥x`、组成；合并合计仍只作展示。
- 套餐目录读取失败只影响套餐 Tab（`packageNotice`），商品开单照常。

## 四、留给下一步的事

1. **整合版逐页验收（M0）**：仍缺真机、六类账号与独立库；套餐页需要新增 A 类验收行（独立价 ≠ 单品价之和、共有物料、缺货、半套、重复提交 10 次只 1 单）。
2. **套餐可售套数口径**：目前取自 `calculatePackageStocks`（排除预留/过期/停用货位，与目录可售量同源），但它是「按物料可用量整除」的理论值；若后续加入组合占位，需要同步。
3. **多货清单（V2.1 ③）**：套餐出库后库房任务必须显示真实物料，而不是「套餐 2 套」；当前 `PickupFulfillmentService` 按原 SALE 分配展示，套餐订单展开后天然是物料行，需在验收中确认。
4. **本人订单（V2.0 M1）**：仍未实现，接口与权限待定稿。
