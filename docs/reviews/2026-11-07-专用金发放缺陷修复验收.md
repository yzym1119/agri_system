# 专用金手动发放缺陷修复验收

日期：2026-11-07
范围：`GrantSpecialFundCommand`、`WalletApplicationService.addSpecialFund`、发放入口测试。
性质：**防御性修复，不改变专用金业务规则、支付瀑布、分账与退款回退语义**；
不新增表/字段、不改 DDL、不动数据库数据。

## 缺陷（修复前，已由只读调查确证）

| # | 问题 | 证据 |
|---|---|---|
| 1 | `GrantSpecialFundCommand` 零约束注解 → `CustomerAdminController:269` 的 `@Valid` 空转 | `GrantSpecialFundCommand.java:13-26`（原） |
| 2 | 无单次发放上限，可无限增发 | `WalletApplicationService.addSpecialFund:320-342`（原） |
| 3 | 正数校验只在领域实体兜底（`CustomerWallet.add:78-80`），且发生在「新建钱包」之后；`customerId=null` 会一路走到建钱包再触发数据库 NOT NULL 错误 | 同上 + `CustomerWallet.java:78-80` |
| 4 | 备注长度无约束，`wallet_transaction.remark` 是 varchar(500) | `ddl/schema.sql`（wallet_transaction 段） |

已核实 `addSpecialFund` **只有手动发放一个调用点**（`CustomerAdminController:282`）；
充值赠送与 VIP 月度直接操作钱包实体 + 写台账，不走该方法，因此服务层防线不会误伤其它来源。

## 实际改动

| 文件 | 改动 |
|---|---|
| `core-application/.../customer/dto/GrantSpecialFundCommand.java` | 加 `@NotNull(customerId)`、`@NotNull/@DecimalMin("0.01")/@Digits(integer=8,fraction=2)(amount)`、`@Size(max=500)(remark)`；`createdBy` 注释明确由登录身份覆盖 |
| `core-application/.../wallet/service/WalletApplicationService.java` | 新增 `MAX_SINGLE_SPECIAL_FUND_GRANT=5000.00` 与 `validateManualGrant(customerId, amount)`，在**任何钱包/流水写入之前**拒绝 null 客户、null/非正/超两位小数/超上限金额 |
| `core-application/src/test/.../SpecialFundGrantValidationTest.java` | 新增 3 项：非法金额零写入、边界合法金额仍写余额与台账（断言 9 个流水字段）、Command 约束的 Bean Validation 直测 |
| `api-admin/src/test/.../SpecialFundGrantHttpTest.java` | 新增 3 项真实 standalone MVC：7 类畸形请求返回 `code=10001` 且不触达钱包服务、超上限服务层拒绝、合法发放仍以真实员工身份写钱包与权益台账（客户端传 `createdBy=999` 被覆盖为 7） |

**上限取值说明**：单次 5000 元是防误操作/滥发的保守默认值，**按用户 2026-11-07 决定由初版
10000 元收紧**；只在服务层定义一次（Command 注解只做格式校验，避免两处硬编码不一致），
可按经营需要在同一常量调整，无需改前端或 DDL。收紧后已重跑完整回归（见下）。
`GlobalExceptionHandler` 已有 `MethodArgumentNotValidException` / `IllegalArgumentException` →
`INVALID_ARGUMENT(10001)` 映射，修复后非法请求由统一业务错误码返回，不再落到数据库异常。

## 遗留风险（本轮未处理，需单独决策）

1. **发放无幂等**：同一请求重复提交仍会重复发放。彻底修复需要业务请求标识 +
   `UNIQUE(store_id, request_key)` 防重（新字段/表），属独立子项，需授权。
2. **无审批流、无累计额度**：本次只加单次上限与格式校验；审批、单人累计发放上限、
   有效期分别属于治理与本次「有效期」子项。
3. ~~**Controller 内两处写入不在同一事务**~~：✅ **已于 2026-11-07 后续修复** ——
   新增 `SpecialFundGrantService` 用单事务包住加余额与写台账，并有真实 Flex 事务回滚测试；
   详见 `docs/reviews/2026-11-07-专用金发放一致性修复与幂等评估.md`。
4. 未做真机、完整 HTTP 权限上下文（Sa-Token 拦截器）或远端 CI 验收；
   HTTP 测试为 standalone MVC，只证明入参边界与身份覆盖。
