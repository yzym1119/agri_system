# 库存预警单位与可信度修复验收

日期：2026-11-02。对应清单B3读取边界与B5真实门店范围子项。

## 问题与影响

本轮继续检查应用层Mapper依赖时，先复现了业务错误，再收敛读取职责：

1. 补货建议读取基准可用量，却标记成商品主单位。商品1箱12瓶、库存36瓶且预留12瓶时，应为可用2箱，旧实现显示24箱。
2. 原销售速度直接相加销售行数量，2箱与6瓶被算成8，正确主单位销量为2.5箱。
3. 库存风险同样用基准可用量比较主单位阈值，可能把低库存判断成积压。
4. 注解销售SQL只按可选storeId过滤，缺少实际租户交集；普通员工不指定门店时可能混入他店销售。随机MySQL测试已复现。
5. 找不到库存事实会被补成0、仍生成可采纳建议；页面将未知状态显示成正常绿色。采纳后还会强行将原低库存状态改成正常，尽管实际库存并未变化。
6. 独立审查进一步发现旧确认框可在列表刷新替换后提交旧建议，迟到查询也可覆盖新门店结果。新增失败测试后已修复。

影响入口为后台库存预警的智能推荐、风险建议及人工采纳阈值。没有新增表、迁移、业务模式、自动采购或价格来源；没有修改库存、采购、销售、退款、资金写入与锁序。原人工采纳仍通过已有商品编辑接口更新阈值。

## 实现

- 新增domain的InventoryPlanningQuery、PlanningStock、SalesVelocity，只提供规划所需的只读证据；基础设施InventoryPlanningMapper/QueryImpl集中查询及结果映射。两个应用服务不再直接依赖OrderItemMapper，旧销售速度入口无调用后移除。
- 库存仍读取唯一inventory_batch_balance，基准余额减预留后除以商品主单位持久直接系数。销售行按自身持久单位系数换算为主单位后求和；缺失或无效系数、非法余额保持未知，不补猜系数。
- SQL同时约束显式门店与真实TenantManager范围；空租户数组直接空结果。管理员无租户未指定门店仍可全店汇总。
- 两应用入口使用原Spring/Flex只读事务；补货公式、观察窗口与季节系数上下限保留。补货库存/销售主单位不一致、缺换算证据或样本不足时，推荐三个阈值均为null。已知零余额与缺失余额明确分开。
- 日期风险仍依据实际有效期；换算未知时保留日期警告、数量为null。风险返回数量单位。
- 页面显示数量去无意义尾零，未知显示待核对，数据不足/未知状态不再显示正常绿色，单条与批量均禁止采纳不可信行。采纳只更新阈值，不假改库存状态。
- 推荐查询绑定代次及页面生命周期；开始新查询即清空旧列表/选择，旧响应不覆盖新查询。采纳固定产品、单位与建议快照，确认后及批量每笔发送前重新验证。刷新、离开页签、卸载后阻止后续发送；已发出的更新不能称被撤销，提示到商品档案核对。
- 报告门禁新增本轮真实MySQL套件为必跑，防止以后条件测试被漏跑或跳过。
