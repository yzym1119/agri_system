# 客户报表范围修复与只读边界收敛

## 问题及范围

清单B3查询边界检查发现真实范围漏洞：ReportAnalysisService仅在storeId非空时按订单关联客户，普通员工不传门店则直接查询共享customer表。客户表没有门店租户列，不能由该表自动限制员工范围。

真实Flex/H2失败测试先RED：本店应为客户[9,7,3,1,6]，原结果却包含他店客户2和无有效订单客户4。管理员及显式门店基线通过。

## 修复与边界

新增CustomerReportQuery与只读CustomerReportRow，承接排行、流失候选及原新增客户计数。报表服务不再直接使用CustomerMapper；门店关联订单查询也移至基础设施，继续使用原OrderMapper的租户与逻辑删除过滤，不停用TenantManager、不替换数据源或事务。

- 仅“无租户限制且未指定门店”的管理员范围保留原全局排行。
- 员工即使未传storeId，也必须经真实租户订单取得客户ID；显式他店继续与真实门店相交。
- 空租户数组、空订单集合返回空，不查询全局客户目录。
- 客户逻辑删除、已删订单、排行排序与SQL条数限制、流失90天及累计消费严格大于1000的筛选保留。新投影只包含原报表所需字段。
- 工作台新增客户数仍为共享客户注册表原全局统计，未在本轮改口径。排行金额也仍是“关联客户的档案累计金额”，不是本店净销售额；本轮修复客户成员范围，不声称所有共享资料已改为门店独占。

补实际HTTP集成：真实ReportCustomerController、ReportAnalysisService、CustomerReportQuery、Sa-Token/RBAC、CurrentUser/DataScope与随机MySQL库。覆盖未授权拒绝、授权后员工默认本店与他店空集、管理员全店、撤权后同token拒绝。权限HTTP套45项通过。首次夹具未给管理员授report:customer导致被正确拒绝，已在测试中明确授权，未放宽生产规则。
