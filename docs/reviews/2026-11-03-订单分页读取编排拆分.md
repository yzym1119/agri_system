# 订单分页读取编排拆分

清单B4正式读取拆分第一步，基线0278c3d。

## 结构及行为

将原queryOrderPage方法移到独立Spring OrderQueryService，原OrderApplicationService新增查询服务依赖，公开入口原样委托。API路径与响应不变；新服务只引用原领域仓储与既有OrderPaymentService财务只读汇总，不引入基础设施实现或第二套查询SQL。

原分页仓储两种重载、返回元数据、订单筛选、前三条物料概览、状态8的整单剩余可退判断、支付和赊销资金展示、门店客户资料请求内复用含查无结果均保留。支付展示静态复用OrderPaymentDisplayPolicy；交付能力调用同一OrderDeliveryEligibility及原仓储，不复制规则。原非null配送类型getter与新直接getter等价。

本轮不提取详情/客户详情，不改创建、POS协调、支付、退款、履约调用或事务边界。新查询服务不加事务、缓存、事件或写入口，原业务订单锁仍在写服务中。原公开入口保留是API兼容委托，不是第二可写来源。

## 验证和失败经过

改前原OrderDeliveryFlow21和支付展示2共23项通过。改后查询夹具构建真实新OrderQueryService，仍调用原公开入口，避免mock新服务掩盖委托错误。原四个不调用列表的手工构造夹具显式传空查询依赖；真实Spring装配由完整API测试覆盖。

首完整回归原整单可退测试出现一项错误：夹具运行中替换facade.itemRepository，新query还保留旧替身，故row.items为空。已同步该真实查询服务的测试仓储引用，不改生产算法、不减断言。原前三行概览、第4行整单剩余可退与后续变更后不可退断言保留。没有将此夹具问题记成生产故障或声称首次全绿。

本轮无运行数据库/预览部署/前端或迁移变更，没有重复前端测试或新增浏览器/手机、性能压测；真实钱货和HTTP范围以原完整条件测试为准。最终回归及独审见完成记录。
