日期：2026-11-10。分支：codex/staff-unified-review；实现基线f2c1121，本报告随本批代码提交，提交号以Git为准。原运行服务和业务库未升级。客户工程mini-customer仍不存在，本报告不代表完整客户登录、身份治理或微信手机交付。

## 已实现的业务行为

1. 新微信先获得真实平台号码的短时证据，再以固定UUID申请开户。手机号/AppID/OpenID不由前端指定；临时凭据不能读取老客户的钱包与订单。无匹配才在同Flex实际READ_COMMITTED事务创建普通客户、三个零余额钱包、当前应用身份及原申请结果；原UUID与当前微信锚防重，唯一索引冲突整笔回滚。返回CREATED仍须新的真实微信登录。
2. 旧客户任一号码命中，包括停用或删除，只进入人工核验。大陆11位、86/+86、ASCII空格和短横分隔统一识别；新建规范保存11位，历史原号码不批量改写。座机、国外与不明确格式不猜成大陆号码。线上/线下先后及并发都不能多建钱包；保留原phone唯一索引。相同号码不等于确认同一人。
3. 新V145唯一一张customer_identity_enrollment记录固定申请与一次决定；身份表要求已有客户，通用日志又没有唯一请求/待办/固定结果，故不能直接代替。不复制钱货、不引入通用流程或第二套可写客户账。原UUID在upsert前后均优先查询，再只按PRIMARY锁；拒绝释放当前锚但不删除原结果。
4. 后台“微信关联核验”已接20条游标队列、详情、同号候选和其他姓名/号码搜索（2至50字、最多20个启用客户）；不默认选人，候选只含基本脱敏资料。关联或拒绝必须填写核验方式和原因，并显式确认。仅对启用、未删除且无同App身份冲突的目标创建身份，不改原联系方式/余额/欠款/积分/券或旧单归属。
5. 读取叠加customer:query与customer:identity:query；处理叠加customer:query与customer:identity:bind。V145真实页面菜单及子操作不自动授角色。路由注册、导航、进入守卫明确all模式，其余旧路由仍any；当前真实员工为审计主体，不接受客户端staffId。

## API与恢复

| 接口 | 行为 |
|---|---|
| POST /auth/client/onboarding/registration | 安全UUID与可选姓名；真实当前PHONE_VERIFIED申请 |
| GET /auth/client/onboarding/registration/{requestKey} | 同AppID/OpenID短时或真实WECHAT客户会话查询原申请，不凭结果发客户token |
| GET /api/admin/customer-identities/enrollments | 按状态、before游标查询 |
| GET /api/admin/customer-identities/enrollments/{id} | 白名单详情与当前候选、原审计 |
| GET /api/admin/customer-identities/enrollments/candidates | 受原客户查询及独立查询权限控制的脱敏候选 |
| POST /api/admin/customer-identities/enrollments/{id}/decision | 固定独立决定UUID/内容/真实员工；相同重放原结果，异体拒绝 |
| GET /api/admin/customer-identities/enrollments/{id}/decisions/{requestKey} | 本员工原决定的完整结果；UNKNOWN不证明未执行，其他决定号/员工为CONFLICT |

页面提交前持久保存原决定A并读回。响应丢失时固定A核对/重试，不修改目标、内容或请求号，不凭申请LINKED就猜本次成功；成功结果逐项核申请、原号、动作、目标、方式、原因。账号/权限变化立即失效旧请求；核验API固定expectedSessionToken，发送拦截器不能借新员工token发送旧操作。本机读取/写入/删除失败或被替换继续待核对。

### 明确拒绝后的安全结束

若目标提交前刚停用，后端拒绝并回滚A的预占，单查A会持续UNKNOWN。独审实际复现此时员工整个页被冻结。修复不以UNKNOWN解冻，不增取消表：用户明确确认“结束本次申请（拒绝）”后，另建独立拒绝B，与固定A一起先保存读回，再复用原decide。

- A先成功：原申请已终态，B不能覆盖；查询原A完整成功后保留关联。
- B先拒绝：申请最终REJECTED，迟到A无法再关联；确认原B完整结果后清等待，客户须重新申请。
- B丢响应：恢复和重试只沿原B，不生成新B或偷偷回退A。
- 第三人先处理：A/B均CONFLICT后显式查看实际处理记录，不当本次成功。
- 未知、内容不完整、会话变化或存储失败：继续保留原记录。结束整次申请不等于撤销已成功关联。
