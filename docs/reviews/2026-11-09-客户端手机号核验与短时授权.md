# 手机号平台核验与短时授权

日期2026-11-09，基线e6f5f2e；依据现行07号手册C0-B②。没有新业务表/字段、原运行库升级或客户/钱包/身份映射创建，数据库最高迁移仍V144。

## 交付与业务边界

新增三个no-store接口：

| 方法/路由 | 行为 |
|---|---|
| POST `/auth/client/onboarding/wechat` | 平台wx.login code换真实身份；已有启用绑定沿AuthService原V144规则登录，返回LINKED/login；未知身份只发PHONE_REQUIRED短时凭据 |
| POST `/auth/client/onboarding/phone` | 当前临时凭据加手机号授权code，向平台提交真实服务端OpenID；核验后发独立PHONE_VERIFIED凭据，截止时间沿原流程，不续期 |
| GET `/auth/client/onboarding/info` | 当前临时凭据只读阶段、Unix秒截止、脱敏号码；不回显token/OpenID/客户ID或任何账款 |

短时身份为ONBOARDING_命名空间，最多原600秒。会话不保存原wxCode或sessionKey；PHONE_VERIFIED仅保存服务端手机号证据，不能当成CUST会话访问订单/钱包。号码、OpenID和最终客户ID均不接受前端自报；不同响应属不同凭据，原待授权凭据不被覆写。

原有效微信绑定仍优先原客户，不根据新号码切换归属。新身份没有自动客户创建；下一阶段必须持久匹配/待关联、首次开户与后台核验/审计/请求防重后才算完成。现customer_identity要求客户非空，本批不以虚构客户绕过，也没有用临时会话代替业务审计。

## 共享平台能力

- 从订阅消息提取WechatAccessTokenService，使用原`wechat:access_token:{AppID}`及原配置；通知和手机号不再各自持有可写缓存。校验平台TTL，不猜缺失过期时间、不缓存失败令牌。
- WechatApiClient统一微信code、令牌、手机号、订阅的HTTP请求：固定HTTPS目的地与接口，禁止重定向，5秒连接、10秒完整响应总截止，65536字节流式上限。超时/中断取消，中断标记恢复；异常不保留含凭据的原URL/消息/原因。
- 不经过普通RestTemplate会打印URL/请求体的调试路径；认证命令、登录结果、授权Reply的诊断字符串隐藏code/token。平台自由文本不进入通知结果或日志。
- 手机号核errcode范围，countryCode=86、纯号码与号码含86/+86前缀一致，应用水印与本地600秒窗口。手机授权code不自动重放；平台明确令牌失效只清共享缓存，要求新授权。
- 原订阅40001清缓存重试一次、43101正常跳过保持，消息结构保持；获取令牌或网络失败不影响主业务事务。

## 验证与发现

1. 新平台/授权契约先以缺类/方法失败，再实现；没有把这项编译失败当成真实平台证据。测试通过假响应校验真实解析、传参和拒绝规则。
2. 原订阅异常会把含令牌URL带入结果：实际原实现回归断言先失败，改共享安全HTTP和固定错误后通过。诊断字符串原code/token泄露同样先失败后修正。
3. 自查错误码2^32被asInt截成0、合法86/+86号码前缀：失败用例定位，补整数范围和一致性规范后通过。未知/缺失/异应用/时间异常/号码不一致均拒绝。
4. 临时授权进行中注销原token，旧函数仍会发新proof；真实MVC失败用例复现。现平台返回后检查原token未变、真实DAO映射有效、原证据相同，取消则拒绝。多响应不覆写另一流程；不将原短时结果当开户请求成功。
5. 独立审查P2：JDK17请求timeout不覆盖已收到响应头后的正文读取，字符串长度检查也要等完整缓冲。真实本机HTTP先回头与首字节、延迟1500ms结束，200ms请求仍成功；超限流也等到尾部，两个断言实际失败。修为sendAsync完整body future总截止并取消，加有界BodySubscriber超限立即取消上游；原两项GREEN，补审关闭。测试转发只在测试HttpClient，生产目的地没有放开。
6. 初次MVC回归JVM测试代理自附加受限；按原策略获准重跑，不更换Mockito实现、不放宽业务断言。初次新增Controller通配符导入被检查拒绝，改显式导入后通过。
