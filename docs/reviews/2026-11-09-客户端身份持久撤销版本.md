# 客户端身份行持久撤销版本

## 问题与本批行为

C0-A每次检查当前身份启用状态/客户归属/AppID，但“停用后再启用、改出关联再改回”会重新满足原条件，旧token可能再次访问。现在使用持久版本区分这两种事实，不能按当前行给旧token补版本。

- V144只在既有customer_identity增加auth_version BIGINT NOT NULL DEFAULT 1，不新增表；历史行初始化1，不改归属、状态、凭据或应用域。status/updated_at不能可靠表达授权撤销代次，因此需要该字段。
- 仓储投影读取版本，不读取sessionKey；保存先读实际原行，核调用方版本，再以WHERE id/auth_version条件更新。客户、身份类型、AppID、身份值或状态改变时递增；凭据刷新与同值保存不增。版本不明、陈旧保存、授权变更溢出明确拒绝，不静默用新版本自动重试授权动作。
- 微信token只保存登录当时的版本，每次本人资源查询实际当前身份并比对。旧无版本、非法版本及原版本不匹配拒绝；即使关联改回或恢复启用，也不能恢复原token。重新正常平台登录可取新token，正常多设备登录不互相撤销。
- 沿原Flex连接、事务和敏感参数手动绑定；保留COALESCE的空凭据忽略语义，不新增凭据日志。外层事务回滚同时撤销本次身份/版本修改。将来治理写入必须经此入口并同事务保存原请求、核验及审计，不能直接Mapper或SQL绕过。
