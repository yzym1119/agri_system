## 一、先修掉一个环境根因（否则所有 HTTP 验证都是假的）

此前 `/health` 与登录返回 `{"error":{"code":"AUTH_REQUIRED"}}`，代码里并无该字符串。
`lsof` 显示端口冲突：**Electron 进程占用 IPv4 `127.0.0.1:52428`**（Express 服务），
而 `api-admin` 的 Java 只绑定 IPv6 `*:52428`；curl 走 IPv4 时命中的是 Electron，不是后端。

修复：停掉随机端口实例，用 `SERVER_PORT=8080` 固定端口重启（8080 空闲）。
现在 `GET http://127.0.0.1:8080/health` → `{"service":"api-admin","status":"UP",...}`，
`POST /auth/staff/login`（`admin/admin123`）返回 token 与完整权限列表。
`.env.local` 已改为 `http://127.0.0.1:8080`；`DEV-SIMULATOR.md` 已写明不要用随机端口。

> 教训：验证 HTTP 前先确认端口归属；`AUTH_REQUIRED` 与「后端未启动」不是一回事。

## 五、清理与边界

- **不自动删除**：测试数据与联调订单都保留，便于继续开发。如需恢复，用插入前备份
  `/tmp/agri_testdata_20261107/before-testdata.sql` 整库还原，或按外键依赖倒序手工清理
  （`order_payment/order_item/order → inventory_movement → inventory_batch_balance → …`），
  不要在有关联订单时直接删商品。
- 成本是明确的测试值，不用于推测真实经营成本；`date_status=UNKNOWN` 未编造生产/有效期。
- 本轮未做模拟器内实际点击、真机、弱网/杀进程或负载验收；HTTP 验证用命令行真实请求，
  不等于微信 GUI 操作通过。
- 临时 `urlCheck=false` 验完必须恢复勾选；不得长期关闭域名/TLS 校验。
