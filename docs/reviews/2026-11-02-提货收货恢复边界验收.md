# 提货收货恢复边界验收

## 范围

承接员工签收恢复，核查提货及采购收货。仅修改两个详情页及其生命周期回归测试，不改后端/数据库/既有运行环境，不发送真实收货、提货或资金请求。

## 失败复现与修复

1. 提货原key=a提交未知后隐藏，本机同scope记录被替换为合法key=b，后台预览也变化为b。旧页面两次重进可接受变化记录并再次提交。失败测试先RED，恢复时保留内存原key核对，缺失/不一致后持续冻结，修后不发第二次确认。
2. 收货提交后切换登录，旧请求失败分支写提示，finally清预览并调用当前新账号的restore。旧请求不应消费另一账号记录或改视图。追加SFC失败测试后，catch/finally核对原epoch和页面代次，修后不改视图、不清原持久记录。
3. 核对已展示收货结果时换登录，旧失败清掉原结果；读取采购详情时换登录，旧失败执行新账号恢复及旧提示。各有先失败用例，补原身份守卫。

收货createReceiptRecovery已有observed一致性、blocked、原请求内容及身份绑定，本轮没有新增另一套恢复模型。提货不重复扣库存/收款，后台仍按原分配及当前剩余量确认。

## 限制及下一步

这是编译生产SFC的页面生命周期与共享契约自动测试，网络/存储故障使用外部边界替身，不是手机真机弱网或杀进程验收。

有限本机记录防误操作，不是防篡改签名；全新进程无法独立证明同scope合法记录在启动前是否人为替换，不能承诺用户清除所有本机数据后仍恢复。后台原状态、真实身份、权限和确认指纹仍是实际写入边界。

下一步按员工工程既定清单继续补真实设备与中断恢复证据，未覆盖项目保持待验；客户小程序、农技和真实支付仍未完成。
