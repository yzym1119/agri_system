# E6 移动销售 · 第一阶段验收

日期：2026-11-07
路径：用户选定「本机 api-admin 联调 + E6 移动销售」；测试号 + 微信开发者工具模拟器开发。
范围：**只改 `packages/mobile-contracts` 与 `mini-staff`**；后端 Java 零改动、无 DDL、无数据改动。

## 一、这一阶段做了什么（以及没做什么）

调查确认 E6 缺的正是「`submitOnce` 的发送回调 + 购物车/结算页」：目录、报价、V133 持久请求
恢复、权限码 `pos:order:create` 后端都已具备，可直接复用，不新开第二套可写来源。

**已实现（第一版最小闭环）**：

| 文件 | 内容 |
|---|---|
| `packages/mobile-contracts/src/sale.ts` | 新增 `./sale` 导出：目录/报价的 `{code:"200",data}` 显式解包、整数分金额换算、`toSaleSummary`（V133 有限摘要）、`buildSaleCommand`（**不含任何成交金额字段**）、订单号守卫 |
| `mini-staff/src/services/sale.ts` | 目录读取、后端报价、`submitSale`（唯一销售写入口，交给 `posRecovery.submitOnce` 的 send 回调） |
| `mini-staff/src/pages/sale/index.vue` | 新页：按名称/编码搜索本店商品 → 数量校验 → **必须先取后端报价** → 购物车 → 提交；结果 COMPLETED 显示订单号，VERIFYING 冻结并引导「核对上次收银」 |
| `mini-staff/src/pages.json`、`workbench/index.vue` | 注册页面 + 按 `pos:order:create` 显示「移动开单」入口 |
| `packages/mobile-contracts/tests/sale.test.cjs` | 4 项契约测试 |
| `mini-staff/tests/sale-pages.test.cjs` | 7 项页面测试 |
| `mini-staff/DEV-SIMULATOR.md` | 修正联调构建方式（HTTP 本机必须 `dev:mp-weixin`）、固定端口启动命令、CLI 导入路径 |

**关键边界**：

- 前端**不计算成交价**：单价只取后端 `suggestedUnitPrice` 作为 `quotedUnitPrice` 指纹；
  提交命令不含 `unitPrice/totalPrice/receiveAmount`；页面小计只作展示并明确标注「以服务端结算为准」。
- 结果未知只返回 `VERIFYING`，**不自动换号重收**；已有未核对原请求时禁止新开单。
- 店员/门店身份由协调器与 Sa-Token 决定，前端只传真实 `staffId/storeId` 供后端校验，不冒充。

**这一版明确未做**（不是"开发完了"）：套餐、优惠券、专用金、积分、会员价、人工改价、赊销/挂账、
客户选择、配送/自提、多支付方式、退款；只支持普通商品 + 现金结算。
这些是后续阶段，不能把第一阶段当成 E6 完成。

## 三、联调前必须知道的限制

1. **本机开发库是空业务库**（`product` 等表 0 行），模拟器里目录会是空的，
   需要在获得授权后准备测试商品，或改连已部署服务器（需 IP:端口）。
2. **未真实下单**：本轮只做接口路径与自动测试验证，没有在数据库创建任何订单/库存/资金事实。
3. 后端端口当前随机为 `52428`；`.env.local` 已写该地址（ignored，不提交），
   重启后端会变，按 `DEV-SIMULATOR.md` 用 `SERVER_PORT=8080` 固定并同步改配置。
4. 联调 HTTP 本机必须 `npm run dev:mp-weixin`（dev 构建），生产构建只接受 HTTPS。
5. 导入开发者工具前需把构建产物 `project.config.json` 的 `touristappid` 换成测试号
   `wxa4ce54aa69b2c3fc`，并临时关闭域名校验（验完恢复）。
