## 逐项核实细节

### 1. CI SpotBugs（P0）
- `.github/workflows/ci-cd.yml:53` 执行 `mvn spotbugs:check -B`，但根 `pom.xml` 未声明 spotbugs-maven-plugin，前缀解析失败：`NoPluginFoundForPrefixException`。
- **修复**：根 pom build/plugins 显式声明 `com.github.spotbugs-maven-plugin:4.8.6.6`；阈值 High + `config/spotbugs-exclude.xml` 精确豁免 2 处刻意设计（CurrentUser 静态持有者注入、OrderQueryService 反射增强降级）。Medium 309 项以 EI_EXPOSE_REP/2 噪声为主，记为技术债。
- **CI 修复链**（4 次迭代后全绿，run 42377695702）：
  1. SpotBugs 步骤改为 `mvn -B -DskipTests install` + 按坐标执行（全新环境无法解析兄弟模块 SNAPSHOT）；
  2. 工作流补 `permissions: packages: write`（新仓库 GITHUB_TOKEN 默认只读，GHCR 推送被拒）；
  3. api-admin/api-client Dockerfile 的 `COPY ../pom.xml` 逃逸构建上下文（BuildKit Forbidden path）→ 改根上下文 + `mvn -pl <module> -am`；
  4. go-offline 需全 reactor pom 齐备 → 补拷兄弟模块 pom。
- **真库 IT 修复**：E2E 在 CI 挂 `FileStorageRepository` Bean 缺失——本地 case-insensitive 文件系统扫描顺序恰好可用而 CI 不可用。已把存储实现从 `@Component + @ConditionalOnBean/OnMissingBean`（Spring 官方明确不可靠的用法）重构进 `AliyunOssConfig` 同类内有序注册：OSS 客户端存在→云存储，否则兜底本地。

### 2. 移动开单 VIP 重定价冲突（P1）
- `mini-staff/src/services/sale.ts:19-25` quoteProduct 不传 customerId。
- `PosOrderCreationService.java:139-177`：按订单客户重新报价（quoteCustomerType），`itemDTO.getQuotedUnitPrice()` 与新报价不一致即抛 `"商品价格已变化，请重新报价后结算"`。
- 复现链路成立：先加购物车（零售价）→ 后选 VIP 客户 → 提交时后端重报价为会员价 → 比对失败。
- **方案**：客户选择先于最终报价；客户变更时清空/重新拉取全部行项目报价；结算页只展示后端报价；后端错误时前端引导逐行重新报价。

### 3. 调账伪造操作人（P1）——已修
- `CustomerAdminController.grantBalance` 原样透传 `command.getCreatedBy()`。
- **修复**：与同文件 `grantSpecialFund` 一致，从 `StpUtil.getLoginIdAsString()` 解析 `STAFF_<id>` 并覆盖 DTO；客户端传入值不再生效。

### 4. 钱包验证码明文返回（P1）
- `WalletClientController.java:35` `resp.put("authCode", code)`，代码注释自认"实际请通过微信/短信下发"。
- **方案**：新增配置 `wallet.auth-code.echo-enabled`（默认 false）；false 时不返回明文，接入可信渠道发送；补发送频率限制、错误次数限制、一次性消费校验（部分已存在需核对）。
- **影响**：当前演示链路依赖回显，需与业务确认渠道后再彻底关闭。

### 5. 跨门店库存权限（P1，验证缺口）
- `InventoryController` 各端点仅 `@SaCheckPermission` + 请求参数 storeId；`InventoryLedgerService.adjust:227` 直接用该 storeId `FOR UPDATE` 查改库存。
- `MobileScanQueryService` 声明"员工查货身份与本店范围"，但写路径未见归属校验。
- **方案**：为普通员工增加"请求 storeId == 员工所属门店"断言（管理层权限码可跨店）；补跨店越权集成测试（查询与修改分别验证）。

### 6. 生产部署缺 api-client（P1）
- `deploy/` 下仅构建 api-admin；nginx 全部 `/api/` 转发 8080；api-client（8081）无容器定义。
- **方案**：Dockerfile.backend 参数化构建 api-admin/api-client 两个镜像（或同镜像双进程）；compose 增 client 服务；nginx 按 `/api/client`、`/api/public` 前缀分流 8081。

### 7. 外部退款未闭环（P0，上线前）
- `OrderPaymentService.refund:341-371`：BALANCE/SPECIAL_FUND 钱包内回退真实；外部支付来源仅累加 refundedAmount 计数，无微信/支付宝原路退款调用。
- **方案**（正式收款上线前）：接入支付平台退款 API + 回调验签 + 对账；在此之前退款接口必须明确标注"仅记账，线下人工退款"，前端提示不可作为自动退款。

### 8. 支付意图事务（P2）——已修
- 原 `createExternalPaymentIntent` 无 `@Transactional`：`expirePendingByOrderId` 与新意图 save 两步可被拆开。
- **修复**：加 `@Transactional(READ_COMMITTED)`。
- **遗留**：`markExpired` 相关"先更新状态再抛异常"路径在事务内会被回滚，属状态机设计问题，与 #9 一并设计（状态流转不应依赖抛异常前的写库，或用 REQUIRES_NEW 记录）。

### 9. 专用金幂等（P2，已知暂缓项）
- `SpecialFundGrantService.grant:23-24` 有事务无幂等键。
- **方案**：复用 V133 `pos_sale_submission` 持久请求模式：发放前插唯一键请求记录（customer_id + request_key 唯一索引），重复请求返回原结果。开放 API 给员工端前必须完成。

### 10. 移动开单搜索只取前 200 条（P2）
- `sale.ts:14` 固定 `pageNum=1&pageSize=200`，前端本地过滤无翻页。
- **方案**：目录接口加 `keyword` 服务端过滤；员工端搜索输入防抖后调服务端；分页加载或"搜索太宽泛请细化"提示。
